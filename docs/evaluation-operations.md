# 평가, 비용, 운영 기준

## 평가 원칙

모델이 그럴듯한 설명을 하는 것과 사건을 올바르게 처리하는 것은 다르다. 비교 기준은 (A) 같은 자료 접근 권한을 가진 개발자의 코딩 AI+수동 제보 처리, (B) 규칙만 있는 파이프라인, (C) TraceBridge다. 자료 접근이 다른 비교로 시간·토큰 우위를 주장하지 않는다. 실제 사건과 재생 가능한 사건을 구분해 보고한다.

| 지표 | 정의 | 실패 신호 |
| --- | --- | --- |
| 사건 상관 정확도 | 제보를 올바른 요청·서비스·환경과 연결한 비율 | 비슷한 로그를 같은 사건으로 오인 |
| 분류 정확도 | 기대된 응답·호출자 계약 오류·실제 결함 등을 올바르게 구분 | 4xx를 무조건 사용자 실수 또는 5xx를 무조건 백엔드 코드 버그로 분류 |
| 잘못된 확정률 / 올바른 보류율 | 근거 없이 원인·해결을 확정한 비율 / 정보 부족을 인식한 비율 | 확신 과장·무한 조사 |
| 라우팅 정확도 | 프로젝트 정책에 맞는 담당 팀·작업 역할·수신자 선택 | 잘못된 담당자/제보자에게 내부 정보 전달 |
| 검증된 조치율 | 수정 전 관련 실패와 수정 후 같은 검사·회귀 통과를 입증한 조치 비율 | 테스트 자체를 바꾸거나 다른 실패를 재현으로 계산 |
| 자동 해결 안전성 | 정책 위반, 배포 후 미회복, 롤백 실패 건수 | 성공 통지 후 실제 오류 지속 |
| 업무 효율 | 제보부터 원인 근거/수용 가능한 조치까지의 시간, 왕복 질문 수, 담당자 검토 시간 | 단순 프롬프트+MD보다 느림 |
| 비용·성능 | 사건당 모델 입력/출력 토큰, 도구 조회 수, 지연, 외부 API·실행 비용 | 전체 로그·코드를 매번 모델에 전송 |

초기 재생 세트에는 (1) 보고한 500과 실제 422, (2) 실제 500과 누락 컬럼/마이그레이션, (3) 같은 시각의 복수 후보, (4) 무관한 로그, (5) 배포 코드와 로컬 HEAD 불일치, (6) 과거 유사 카드와 다른 현재 원인, (7) 거부해야 할 패치·도구 인자, (8) 보안 의심/권한별 알림, (9) 수정 후 회귀 실패, (10) 외부 연결기 시간 초과를 포함한다. 합성 fixture는 회귀에 유용하지만 실서비스 성능의 증거로만 사용하지 않는다.

현재 [사건 기억 단계](stage-3-memory.md)는 `memory_search.hit_count/strategy/elapsed_ms`, 카드별 현재 재확인과 실행이 붙은 근거 참조를 기록한다. DB 재연결·검토 변화·반복/다른 현재 원인/충돌의 합성 검증을 수행했다. 단독 재현의 검색 시간은 약 4ms였으나 동일 자료 접근권한 비교 실험, 빠른 응답·도구 호출 절감이나 실사건 성능을 검증하지 않았다. 이 기록은 사건 기억의 기능 검증이며 비교 평가 단계를 시작한 것으로 집계하지 않는다.

## 토큰과 지연의 설계

정확한 ID 조회, 계약 대조, 기억 카드의 정확/전문 검색에는 LLM이 필요 없다. 모호할 때만 모델에 제한된 근거를 제공해 다음 조회를 선택하게 한다. 기본 예산 후보는 사건당 LLM 0~4회, 읽기 도구 최대 6회, 모델에 로그 최대 20줄·코드 조각 최대 6개·과거 카드 최대 2개다. 사진 OCR는 별도 서비스 호출로 기록하고 사진 시각 해석은 LLM 예산에 포함한다. 한도에 닿으면 원인을 확정하지 않고 보류한다. 수치는 측정에 따라 조정하며 토큰 절감을 보장하지 않는다.

사건별 `prompt_tokens`, `completion_tokens`, 모델 호출 수, 도구별 결과 크기, 캐시 적중, 비용, 지연을 남긴다. 간단한 사건에서는 모델 0회가 목표다. 어려운 사건은 토큰이 늘더라도 잘못된 확정과 사람의 재조사를 줄이는지 본다. 과거 카드 검색이 실제 도구 호출·소요 시간을 줄이지 않으면 검색 복잡성을 늘리지 않는다.

## 에이전트 품질 검증

규칙 검사와 통합 재생으로 상태 전이·권한·근거 ID·도구 범위를 검증한다. 모델 선택의 품질은 입력 자료가 다른 변형 사례에서 같은 가설을 고집하지 않는지 확인한다. 최소한 한 조사에서 가설, 반증 목적 조회, 결과에 따른 방향 변경을 실행 기록으로 보여준다.

[NeMo Agent Toolkit 평가](https://docs.nvidia.com/nemo/agent-toolkit/latest/workflows/evaluate.html)는 워크플로 실행 경로를 평가하는 도구다. 사용자 제공 대회 이미지의 `NeMo Framework 또는 NeMo Microservices` 조건과는 별개다. 실제 [NeMo Evaluator Microservice의 agentic 평가](https://docs.nvidia.com/nemo/microservices/25.10.0/evaluate/flows/agentic.html)를 사용하는 경우 데이터셋·서비스 endpoint·job ID·결과를 기록한다. 모델 평가 점수 하나로 실제 문제 해결을 증명하지 않고 위의 프로그램 검증과 사람의 결과 검토를 함께 사용한다.

## 운영·관측

작업 큐는 `queued/running/waiting_input/waiting_review/completed/failed`와 사건 상태를 분리한다. 외부 로그·SCM·CI·통지 호출에 개별 시간 제한·재시도·중복 방지 키를 적용한다. 모델 타임아웃이나 부분 자료 접근 실패 시 확정 수준을 낮추고 누락된 자료를 표시한다. 인입량과 사용자별/프로젝트별 한도로 비용·남용을 제어한다. 감사 기록에는 정책 결정, 도구 호출 범위, 변경·배포 작업, 수신자·전송 결과를 남기되 비밀/개인정보 원문은 남기지 않는다.

운영 대시보드는 사건 발생/중복/분류·중요도 분포, 미해결·담당자 대기, 자동화 수준별 성공/중단/롤백, 조사 시간·비용·토큰, 잘못된 확정·제보자 피드백을 보여준다. 과거 사건의 재사용이 품질을 악화시키면 기억 검색을 끄거나 순위를 조정할 수 있어야 한다.

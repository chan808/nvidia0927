# 로컬 프로젝트 경로와 연결 진단

현재 기본 화면은 [간편 등록·글/사진 제보](simple-project.md)다. 아래 경로·서비스별 자료 설정은 **고급 설정**에서 사용한다. 기본 화면의 연결 상태는 오른쪽에 표시한다.

기본 화면의 **프로젝트 정보 수정**에서 이름·폴더·실행 주소를 편집한다. 서비스별 경로·로그·계약과 직접 진단은 **고급 설정**에서 연다. 글/사진 제보는 같은 화면의 **문제 알려주기**에서 한다.

## 경로 설정

로컬 소유자 웹을 `TRACEBRIDGE_ALLOW_PROJECT_REGISTRATION=1`로 실행하면 **이 PC의 경로·서비스 주소 설정**이 나타난다. 연결된 프로젝트 ID의 기존 값을 불러와 수정한다.

- 기준 저장소와 서비스별 저장소·코드 경로: 프론트와 백엔드가 다른 디렉터리나 드라이브에 있어도 등록할 수 있다.
- 로그 파일과 서비스 범위: 요청 ID·시각·서비스·환경을 연결할 자료를 지정한다.
- OpenAPI·DTO·호출자 자료: 기본 경로와 서비스별 경로를 지정한다.
- 기본 및 서비스별 상태 확인 URL: 실행기가 있는 PC의 loopback HTTP 주소와 명시적 포트를 사용한다. URL에 인증 정보나 query를 넣을 수 없고 redirect는 따라가지 않는다.
- 실행 버전 자료: 기본 JSON 파일/로그 필드, 서비스별 설정은 연결 JSON에서 지정한다.

경로는 **웹 프로그램을 실행하는 PC** 기준이다. 다른 PC의 경로는 해당 PC의 로컬 등록 화면이나 프로필 파일에서 설정한다. 중앙 배포 웹에서는 로컬 경로 입력을 켜지 않는다. 웹과 PC 실행기는 같은 `TRACEBRIDGE_PROJECT_REGISTRY` 등록 폴더를 사용해야 한다.

새 프로젝트를 이 PC의 간편 화면에서 등록하면 프로젝트 하나로 범위를 제한한 PC 실행기를 자동 연결한다. 다른 PC의 실행기는 [별도 페어링](real-projects.md#배포-웹과-pc-연결)한다. 기존 프로젝트 수정은 ID와 정책 참조를 보존하고, 다른 창에서 이미 수정한 설정에는 덮어쓰지 않는다. 설정이 변경되면 새 manifest가 게시될 때까지 화면에 차이를 안내한다. 수정 권한과 원본 자동 적용 허가는 별도 설정이다.

Windows에서 조회 중인 파일이 교체를 잠시 막으면 프로필·정책 저장은 최대 1.4초의 제한된 대기 후 원자적 교체를 재시도한다. 영구 접근 거부는 오류로 남고 이전 파일을 보존한다. 대기 중 다른 창이 프로필을 바꾸면 덮어쓰기를 거부한다.

## 연결 확인

| 화면 항목 | 확인하는 사실 |
| --- | --- |
| PC 실행기 | 중앙 API에 등록 PC가 연결돼 있는지 |
| 서비스 응답 | 등록 URL의 HTTP 응답과 알려진 health 상태 |
| 자료 조사 준비 | 선택한 서비스의 코드 경로·요청 로그·OpenAPI·실행 버전 자료가 연결돼 있는지 |

실행기는 약 30초마다 점검 결과를 게시한다. **PC 상태 새로 불러오기**는 최신 게시 결과를 읽는다. 같은 PC에서는 **이 PC에서 코드·로그·서비스 다시 점검**으로 즉시 읽기 전용 점검을 실행할 수 있다. 직접 점검의 출처와 시각은 등록 PC의 게시 결과와 구분해 표시한다. 이 점검은 외부 모델을 호출하지 않는다.

연결 진단은 선택한 서비스의 자료만 사용한다. 코드 범위가 없는 로그·계약 전용 저장소는 코드 연결의 증거로 세지 않는다. 마지막 결과가 120초보다 오래됐거나 PC가 오프라인이면 현재 서비스 상태를 미확인으로 표시한다. 30초보다 먼 미래의 시각도 최신 결과로 인정하지 않는다.

| 응답 | 표시와 다음 작업 |
| --- | --- |
| 2xx / UP | HTTP 정상 응답 / 정상 상태 응답. 필요한 기능은 별도 재현·회귀 검사 |
| DOWN / OUT_OF_SERVICE / 5xx | 비정상 상태 응답 / 서비스 사용 불가. 기동·포트·로그 확인 |
| 연결 실패 | 실행 중인지, 등록 포트와 접근 상태 확인 |
| 401 / 403 | 서버 응답은 있으나 인증 때문에 상태 미확인 |
| 404 | 상태 확인 endpoint 경로 재확인 |
| redirect | 이동 전 응답만 확인. 등록 URL 재확인 |
| 주소 없음 / 해석 실패 / 오래된 결과 | 미등록 또는 미확인. 연결 설정과 관측 갱신 |

자료 조사 준비의 **기본 연결 확인**은 파일 접근과 자료 존재의 확인이다. 실제 사건의 요청 대응, 자료 내용의 정확성, 실행 snapshot 일치, 모든 기능 정상 동작을 뜻하지 않는다. 원본 적용 후 사건 해결은 [서비스 회복 검사](project-recovery.md)의 별도 근거가 필요하다.

## 버전 갱신과 후속 범위

API·웹·PC 실행기를 같은 소스 버전으로 재시작하면 서비스별 상세 진단이 전달된다. 새 실행기는 구 API가 새 진단 필드를 거부할 경우 기존 manifest 형식으로 연결한다. 이 경우 세부 자료는 API·실행기 갱신 또는 같은 PC의 직접 점검으로 확인한다.

현재 연결 진단은 등록된 파일과 상태 URL을 읽는다. 대상 앱 자동 기동, 전체 API 탐색, 브라우저 사용자 여정, 상시 성능/취약점 탐지는 후속 기능이다. 다음 단계로 프로젝트별 실행 명령·허용 API·핵심 시나리오·검사 예산을 등록하면 실제 테스트의 범위를 명확히 확장할 수 있다.

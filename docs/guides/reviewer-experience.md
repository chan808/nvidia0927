# 심사위원의 첫 체험

배포 첫 화면 `/`는 로그인 없이 열고, 기존 소유자 화면은 `/owner/`에서 인증한다. 웹 서버의 경로를 심사위원 PC 경로로 취급하지 않는다.

## 설치 없이 먼저 확인

**실제 버그 해결 흐름 실행**은 서버의 새 예제 사본에서 실제 HTTP 요청·로그·검사·수정 적용·회복 확인을 수행한다. 실행 결과의 request ID, diff, 소스 snapshot을 함께 표시하며 종료 후 임시 프로젝트와 프로세스를 정리한다. 실행 실패나 동시 요청 제한은 오류로 표시한다.

버그는 “0~5개 신청 가능” 계약의 구현이 `0 <= count < 5`인 경계값 오류다. 5개 요청은 HTTP 500과 실패 검사를 만들고, `<= 5` 패치 후 같은 검사·독립 회귀·실제 HTTP 200·실행 소스 snapshot을 확인한다.

기본 수정안은 **준비된 고정 예제 패치**다. 로그 조사·검증·적용·회복은 실제 코드 경로로 실행하지만 모델을 호출하지 않으며 AI 수정 성능의 증거가 아니다.

## PC에서 직접 체험

1. Windows에 Python 3.12가 설치돼 있는지 확인한다.
2. **PC 실행기 ZIP 다운로드**를 누르고 압축을 푼 뒤 `START.cmd`를 실행한다.
3. 처음 한 번 최소 의존성을 설치하고 바탕화면 `TraceBridge-Review/<체험 ID>`의 로컬 웹을 연다. 설치 터미널은 체험 중 열어 둔다.
4. **버그 예제 다운로드·실행**을 누르면 새 `TraceBridge-Demo-<체험 ID>` 폴더와 loopback 앱을 만든다. 기존 폴더가 있으면 덮어쓰지 않는다.
5. **실행 중인 예제 앱 열기**에서 4개·5개·6개 신청을 확인하거나 **5개 신청 버그 재현·조사**를 누른다.
6. **예제 수정안 검증**에서 수정 전 실패·수정 후 성공·회귀 성공과 diff를 확인한다.
7. diff 확인 체크 후 **예제에 수정 적용**, **5개 신청·회귀 API 회복 확인**을 누른다.
8. 필요하면 **예제 앱 종료**를 누르고 실행기 터미널을 종료한다. 생성한 폴더와 기록은 PC에 남는다.

PC 실행기는 서버로 먼저 연결하고, 등록 폴더와 loopback 서비스의 상태를 게시한다. PC 연결과 대상 서비스 응답은 별도로 표시한다. 서버 연결 실패 중에도 기본 로컬 체험을 실행할 수 있다.

## 내 프로젝트 연결

별도 다운로드의 **내 프로젝트 등록**에서 이름·전체 폴더 경로·선택적 loopback 실행 주소와 JSONL 요청 로그를 등록한다. 폴더 등록만으로 명령 실행·원본 수정 권한을 부여하지 않는다. 같은 체험 ID의 예제와 내 프로젝트를 섞지 않도록 새 다운로드로 별도 체험을 시작한다.

기본 증상 조사는 PC에서 수행한다. **NVIDIA 분석 서비스에 보내 AI로 조사**를 선택하면 필요한 제보·코드·로그가 서버 및 NVIDIA에 전송된다. 서버 모델 키가 필요하며 내려받는 파일에 키·운영자 토큰·기존 프로젝트·사건 DB를 포함하지 않는다. 공개 AI 수정은 기존 Docker 검사 정책을 요구한다.

다운로드마다 새 프로젝트 ID와 24시간 유효한 체험 권한을 발급한다. 그 권한으로 다른 사람의 프로젝트·작업·소유자 API에 접근할 수 없다. 페어링 코드는 실행 시 발급하므로 첫 설치가 5분을 넘겨도 코드를 미리 만료시키지 않는다. 다운로드·브라우저 실행·조사 횟수와 동시 실행에 상한을 둔다.

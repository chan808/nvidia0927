# 사건 지식 검토와 답변 품질 비교

실제 프로젝트가 실행되지 않는 환경에서도 합성 사건으로 카드 검토·검색 재사용·기억 끔/켬 비교를 확인할 수 있다. 이 결과는 실제 사용자 제보의 정확도를 대신하지 않는다.

## 카드 검토

소유자 웹의 **연결된 프로젝트 → 고급 설정 → 사건 지식 검토**에서 **사건 카드 불러오기**를 누르면 프로젝트별 검토 대기·승인·수정 승인·재사용 제외 카드를 본다. 카드의 저장된 판단과 다음 조치, 원인·후보·회복의 기록 상태를 확인한 뒤 검토 결과와 근거 메모를 남긴다.

| 검토 결과 | 뜻 |
| --- | --- |
| 사용 안내가 맞음 | 담당자가 안내의 적용 조건을 확인한 과거 사례 |
| 제품 결함 확인 | 담당자가 결함을 확인한 과거 사례. 기록된 자동 재현·회복과는 별개 |
| 서비스 회복 확인 | 등록된 회복 검사 결과가 기록된 경우에만 선택 가능 |
| 근거 부족·재사용 제외 | 검색에 사용하지 않는 카드 |

승인된 카드는 같은 프로젝트의 승인 카드 검색에 들어가고, 제외하면 검색·벡터에서 빠진다. 담당자 라벨은 현재 제보의 증거가 아니므로 조사 때 현재 요청·버전·계약을 다시 확인한다. 오래된 화면의 승인 요청은 카드 revision 불일치로 거절된다. 기존 카드 4건을 일괄 승인하거나 실제 `daily-local`의 검토 상태를 변경하지 않았다.

## 합성 답변 품질 비교

아래 명령은 고정 12건을 동일 자료·조건에서 기억 끔/켬으로 각각 실행한다. 기본 `doubles`는 명시적인 모델·OCR 테스트 더블만 사용하고 외부 모델을 호출하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_response_quality --mode doubles --output output/knowledge-review/evaluations
```

출력 디렉터리의 `response-quality.json`에는 각 사례의 판정 통과, 잘못된 안내, 근거 없는 원인·해결 확정, 필요한 추가 질문, 과거 카드 검색 여부, 관측된 모델 호출 수와 합성 실행 시간이 짝으로 기록된다. 짝이 없거나 출처·실행 범위·기대 결과가 다르면 비교에서 제외한다. 기존 `summary.json`과 원본 실행 기록도 함께 보존한다.

이번 합성 `doubles` 실행은 **12쌍 모두 고정 검사 통과**, 기억 켬의 과거 카드 검색 11건, 판정 개선 0건·악화 0건, 외부 호출 0회였다. 검색된 카드가 많아도 대응 품질 개선으로 해석하지 않는다. `local` 경로는 양쪽 모두 10/12이며 고정 검사 실패가 있으므로 평가 명령이 실패 코드를 낸다. 현재 고정 사진 사례는 사진과 글이 함께 있으며 사진만 있는 제보의 브라우저·실모델 종단 평가는 별도다.

실제 품질 개선을 판단하려면 담당자가 동작·원인·회복의 정답을 붙인 실제 사례를 같은 평가 계약으로 기록하고, 기억 끔/켬의 잘못된 안내·보류·회복 결과를 비교해야 한다. [검증 기록](../validation/knowledge-review.md)과 [실제 사건 검색 평가](operational-hardening.md#실제-사건으로-검색-품질-평가)를 함께 참고한다.

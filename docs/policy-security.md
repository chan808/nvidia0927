# 권한, 자동화, 데이터 보호 정책

이 문서는 목표 서비스의 정책 계약이다. 현재 Streamlit 데모에 인증·다중 조직 격리·자동 배포가 구현됐다는 뜻이 아니다. 불특정 다수가 제보할 수 있는 제품에서 **제보 권한, 내부 조사 권한, 코드 변경 권한, 배포 권한은 별도**로 평가한다. [OWASP 인가 원칙](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)에 맞춰 기본 거절과 최소 권한을 사용한다.

## 접수·조회·실행 권한

- 프로젝트 관리자가 `public_report_intake`를 켜야 익명 제보를 받는다. 익명 사용자는 추측하기 어려운 만료형 접수 확인 토큰으로 제한된 상태만 확인하며 사건 내부 근거·다른 제보·담당자 정보를 볼 수 없다. 공개 접수에는 크기·속도 제한, 스팸 방지, 첨부 검사, 중복 처리 정책을 둔다.
- 조직·프로젝트·환경·사건 범위는 서버가 인증 주체와 정책으로 확인한다. 요청의 `project_id`나 모델 도구 인자만 신뢰하지 않는다. 민감 보안 제보는 별도 제한된 대기열과 수신자를 사용한다.
- 로그/APM/DB 연결기는 각각 읽기 전용 계정으로 시작한다. DB 도구는 등록된 매개변수화 진단 조회, 스키마·마이그레이션 상태에 한정한다. 운영 데이터 변경과 임의 SQL 실행 도구는 진단 에이전트에 제공하지 않는다.
- 코드 작업자는 사건에 선택된 저장소의 격리 사본에만 쓴다. 변경 가능한 경로·파일 수·diff 크기·테스트 명령·실행 시간·네트워크를 정책으로 제한한다. 배포 자격 증명은 별도 작업자에게만 제공한다.

## 자동화 수준

프로젝트·환경·책임 영역별로 아래 상한을 설정한다. 중요도, 분류, 변경 파일, 검증 결과에 따라 **이번 사건에서 실제 허용되는 수준은 더 낮아질 수 있다.** 모델은 수준을 제안할 수 있지만 정책 엔진의 허가를 대체하지 않는다.

| 수준 | 허용 행동 | 완료 보고 |
| --- | --- | --- |
| `A0 TRIAGE` | 증거 조사·분류·담당자 지정·안내 | 관측, 근거, 미확인 사항, 다음 조치 |
| `A1 PLAN` | 해결 계획·테스트 계획 작성 | 대상 팀과 검토할 계획. 코드 변경 없음 |
| `A2 PREPARE_CHANGE` | 격리 사본에서 재현·패치·회귀 검사, 검토용 diff/PR | 수정 전후 결과와 남은 위험. 병합·배포 없음 |
| `A3 AUTO_NONPROD` | 사전 승인된 비운영 환경에 적용·재검증 | 적용 버전, 재검증, 실패 시 복구 상태 |
| `A4 AUTO_RELEASE` | 엄격한 프로젝트 정책을 만족한 낮은 위험 변경의 자동 병합/운영 배포·사후 확인 | 실행 경로, 배포 버전, 관측 회복·롤백 여부, 담당자 통지 |

`A0`가 기본값이다. `A2` 이상은 프로젝트 소유자의 명시적 설정, 대상 저장소/환경 허용, 감사 가능한 실행이 필요하다. `A4`는 제품 목표의 **선택 기능**이며 현재 구현이 아니다. 운영 자동 해결을 허용하려면 변경 유형·서비스·시간대·CI 게이트·승인 조건·점진 배포·사후 모니터링·자동 중단/롤백이 설정돼야 한다. 인증/권한, 결제, 비밀, 스키마·데이터 마이그레이션, 보안 의심, 광범위한 인프라 변경은 기본적으로 `A4` 대상에서 제외하고 담당자 검토로 보낸다. 프로젝트가 승인한 고정 runbook과 일반 코드 패치를 동일 권한으로 취급하지 않는다.

**자동 성공 판정:** 테스트가 통과했다는 사실, 코드가 병합됐다는 사실, 서비스가 회복됐다는 사실은 다른 상태다. `A4`에서도 배포 후 같은 증상·오류율이 지정된 기간 동안 회복됐다는 근거가 없으면 해결로 닫지 않는다. 배포 확인 실패·새로운 오류·모니터 신호 악화 시 자동 중단/복구하고 온콜에 전달한다. 복구 실패를 숨기거나 성공 통지를 보내지 않는다.

## 라우팅과 보고 권한

소유자 설정/CODEOWNERS·온콜·사건 분류가 알림 수신자를 결정한다. 모델이 제안한 책임자는 정책에 존재하는 사람/팀과 대조한다. 소유자 충돌·누락은 기본 triage 큐로 보낸다. 제보자는 자신의 사건 진행 상태와 공개 가능한 결론만 받는다. 내부 담당자는 근거·코드·테스트·정책 결정을 본다. 보안 의심의 상세 정보는 제한된 수신자에게만 전달한다.

통지는 프로젝트 관리자가 연결한 채널과 템플릿으로만 전송한다. 외부 메시지, PR 생성, 배포는 사건 처리와 별도 감사 가능한 작업이다. 전송 실패에는 재시도·중복 방지와 실패 상태를 남긴다. 제보자에게 불필요한 내부 저장소 경로, 로그 원문, 계정 정보, 공격 가능한 세부 사항을 노출하지 않는다.

## 모델·자료·실행 경계

제보·로그·코드·과거 사건 카드는 모두 신뢰할 수 없는 입력이다. 그 안의 “다른 도구를 실행하라”는 문장은 에이전트 권한을 바꾸지 못한다. 모델 응답은 구조화해 검증하고, 근거 ID의 존재와 프로젝트 범위, 도구 인자, 수정 경로, 정책 버전을 프로그램이 확인한다. 모델이 작성한 임의 쉘·SQL·URL은 실행하지 않는다.

외부 모델로 전송하는 자료는 프로젝트 정책에서 허용한 비식별화 발췌로 제한한다. 비밀·세션·토큰·민감 개인정보를 저장/전송/표시하지 않도록 수집 단계와 출력 단계에서 검사한다. 비식별화 실패 가능성 때문에 민감 프로젝트에는 외부 전송 자체를 끄거나 허가된 내부 모델을 사용한다. [OWASP 로그 지침](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)은 토큰·비밀번호·개인정보·소스 코드 같은 자료의 직접 기록을 제한한다.

수정·테스트 실행은 격리된 작업 공간, 허용 목록 환경 변수, 시간·자원·네트워크 제한, 비밀 없는 테스트 자격 증명을 전제로 한다. [NVIDIA OpenShell의 파일·네트워크 정책](https://docs.nvidia.com/openshell/reference/policy-schema)을 사용할 수 있으나 연결 여부는 실제 실행으로 확인해야 한다. 현재 `tracebridge/repro.py`의 샘플 테스트 프로세스는 임의 프로젝트 코드를 안전하게 실행하는 환경으로 간주하지 않는다.

## 정책 변경과 검토

정책은 프로젝트별 버전 관리와 관리자 승인, 변경 전후 diff, 적용 시각, 롤백을 갖는다. 사건은 **당시 평가한 정책 버전**을 기록한다. 모델/프롬프트, 작업 스킬, 연결기, 허용 명령이 바뀌면 [평가](evaluation-operations.md)의 재생 사례를 돌리고 권한·자료 범위 회귀를 확인한다. 자동화 수준 상향은 기존 사건에 소급 적용하지 않는다.

## 현재 로컬 A2의 좁은 구현

[4단계](stage-4-change.md)는 이번 사용자 지시가 허용한 workspace 내부의 `tracebridge-seed-signup` 개발/테스트 대상 1개를 [등록 정책](../examples/change_policy/seed-signup-a2-v1.json)과 프로그램의 고정 digest로 허용한다. 권한을 실제 Agolive 원본·운영 실행으로 확대하지 않는다. 저장된 최신 작업 후보/출처와 정확 상관·완전성·dev 범위·씨드 snapshot을 검사하며 제보 문구/과거 카드/모델에 정책 변경 도구를 제공하지 않는다. 로컬 파일 소유자가 등록 코드·정책을 신뢰하는 내부 경로이며 인증된 관리자 정책 API는 없다.

후보의 요청 사전 키 문자열만 바꾸고 전체 AST의 나머지와 검사/입력 해시를 보존한다. 프로그램이 등록 ID를 고정 argv로 실행하고 기준과 후보의 입력·설정·timeout을 동일하게 검사한다. 별도 사본·`-I -B`·허용 목록 환경·timeout이 실제 제한이다. **OS 네트워크/파일/자원 격리와 OpenShell 적용은 검증하지 않았다.** 따라서 해시로 등록된 신뢰 가능한 작은 씨드 코드만 실행하며 임의 프로젝트의 안전한 실행을 주장하지 않는다. 후보 검사·회귀가 통과해도 `CHANGE_PREPARED/WAITING_REVIEW`이며 원본 적용·배포·회복과 카드 검토를 별개로 둔다.

# 현재 구현 상태

기준: 2026-09-29 적용 보고·서비스 확인 보완. 현재 사실을 요약합니다. 제품 전체의 목표는 [설계 문서](README.md#설계)와 구분합니다.

최신 후속 구현은 **PC의 원본 적용 결과 보고와 적용 후 API 확인**이다. 검토된 후보의 diff·snapshot·정책·사건 revision을 대조한 멱등 보고, 신고 API 기대 결과와 별도 회귀 검사, 실제 로드한 snapshot 대응 헤더와 관측 기간을 연결했다. 성공은 `RESOLVED`, 실패는 `REOPENED`, 버전/응답 부족은 `OPEN`으로 저장하고 최신 기록에서 후속 조사를 이어간다. 공개 합성 프로젝트의 실제 파일 적용·HTTP, 중앙 SQLite/PostgreSQL, Streamlit AppTest로 확인했다. 자동 배포/롤백·브라우저 클릭 여정·daily 실제 장애 회복은 완료 범위가 아니다. [사용법](guides/project-recovery.md), [검증 기록](validation/project-recovery.md)을 확인한다.

최신 전체 **689개 통과(240.36초)**에는 실제 PostgreSQL 32개가 포함된다. 최종 재검토에서 사건 저장 후 중앙 커밋 중단 시 감사 이력이 빠지는 문제를 수정하고 두 DB의 재전송 복구를 확인했다. 현재 웹·API·PC 실행기에 반영했고 기존 작업 4건과 사건·카드·감사 이력·프로필·정책·인증 파일을 보존했다. daily의 원본 적용 권한은 비활성이며 회복 정책은 등록하지 않았다.

이전 후속 구현은 **daily의 실제 개발 HTTP 요청 연결**이다. 프론트의 요청 ID·발생 시각·실패 메타데이터, backend의 제한된 JSONL·빌드 SHA/dirty 기록, 개발 로그인 한 endpoint의 소스 해시 대응 계약/DTO와 별도 서비스 health를 연결했다. 실제 HTTP 400 → 프론트 프록시 → TraceBridge API → 페어링 PC의 `EXACT_ID`와 모델 0회를 확인했다. 당시 전체 **650개 통과(175.86초)**에는 실제 PostgreSQL 30개가 포함된다. 기존 daily 데이터와 원본 적용 권한은 변경하지 않았다. 입력 검증 실패를 별도 개발 DB에서 재현한 것으로 실제 사용자 장애 해결과 구분한다. [사용법](guides/daily-observation.md), [검증·남은 범위](validation/daily-observation.md)를 확인한다.

그전 후속 구현은 **중앙 PostgreSQL + pgvector**, 작업/사건/카드/이력 통합 커밋, 동시 claim·epoch, 원 JSON/해시 보존 이전·역방향 export, 백그라운드 색인과 검색 쿼리 캐시/예산이다. 재검토에서 검색 중 정정·반려, 색인 중단·취소·만료, 프로젝트 참조, 잘못된 API 입력, 구버전 이전 검증, 사건 revision과 수정 이력 정렬을 보완했다. 최종 **632개 통과(198.93초)**에 실제 PostgreSQL 검사 30개가 포함된다. [운영 명령](guides/postgres-rag.md), [재검토·소스 해시·남은 조건](validation/postgres-rag-review.md), [초기 595개 검사](validation/postgres-rag.md)를 확인한다. PC SQLite와 기존 서버 호환 경로는 유지한다. 실제 운영 DB 전환·NIM 검색 품질·실사건 적용 후 확인·팀 인증·자동 배포는 완료 범위가 아니다.

2026-09-29 후속 고도화로 소유자 평가의 우선순위 큐·난이도별 조사 예산, 저장된 작업 목록/재열기·상태/모델 이력, 서비스·환경 범위 검색과 선택적 NIM 임베딩/RRF 검색을 추가했다. [설정·평가·후속 순서](guides/operational-hardening.md)를 확인한다. 독립 Vector DB·임베딩 실호출·실사건 품질 향상·자동 중요도/난이도 추정은 검증/구현 범위와 구분한다.

이전 SQLite 고도화 단계의 전체 회귀는 **579개 통과(108.56초)**다. 새 화면은 AppTest로 검증했으며 실제 브라우저의 이전 551개 GUI 시점 기록과 구분한다. [이번 검증·한계와 소스 해시](validation/operational-hardening.md)를 확인한다.

## 제공하는 기능

2026-09-29 **웹/서버의 작업·모델 관리 + 프로젝트 PC의 로컬 조사 실행기**를 소유자 전용 시범으로 구현했다. 실제 다중 경로·서비스별 로그/계약/버전, 모노레포 Git root, 코드 파일 탐색·읽기, 등록된 검사·일반 프로젝트 후보·검토 후 원본 적용을 제공한다. HTTP 페어링·범위 제한 실행기 토큰·임대·모델 단계 캐시·확보 결과 재전송·취소 확인과 배포 웹 화면도 추가했다. [실제 운영 사용법](guides/real-projects.md)과 [실행 검증](validation/real-project-operations.md)을 확인한다. 공개 다중 사용자 인증·원격 사진 처리·자동 배포/회복은 구현하지 않았다.

최신 [로컬 GUI 전체 회귀 551개 통과(110.50초)](validation/local-gui-final.md), 실제 브라우저의 등록·제보·같은 사건 답변·실모델 후보·검토 후 원본 적용·재열기, 실행기 오프라인 대기와 재연결을 확인했다. 별도 공개 프로젝트에서 적용했고 daily의 실제 장애 해결이나 공개 HTTPS 배포 성공을 뜻하지 않는다. [이전 연결 검증](validation/real-project-operations.md)의 daily 프론트 229개 및 당시 547개 회귀와 [경로 등록 515개 회귀](validation/multi-repository.md)는 각 시점의 기록이다.

## 검증된 범위

[최종 통합 기록](validation/main-integration.md)에 전체 회귀 **499개 통과(174.74초)**와 패키징 보완 후 전용 검사 **27개 통과**가 기록돼 있습니다. 이 수치는 당시 코드의 실행 결과이며 문서 정리 작업의 새 전체 검사 결과가 아닙니다.

- CLI·화면 검사·SQLite·재시작·매뉴얼·정책·사본 검증·계측과 평가를 로컬에서 확인했습니다.
- 기존 Python 환경에서 압축 해제한 묶음의 재생을 확인했습니다. 새 환경 설치 성공은 별도입니다.
- NeMo Retriever OCR·Nemotron 실제 호출 증거는 [과거 NVIDIA 기록](validation/nvidia-validation.md)에 있습니다.
- 기억 켬/끔과 단일 프롬프트·일반 코딩 에이전트의 우위, 시간·토큰 절감은 입증하지 않았습니다.

## 남은 검증과 후속 기능

1. 허가된 실제 사건의 화면·동작·시각·환경을 실제 로그·실행 SHA·계약·호출자와 연결해 검증
2. 현재 조사 스키마의 실모델 반복·OCR·서빙 실패·NAT 종단 확인
3. 새 환경 의존성 설치와 같은 입력·권한·예산의 비교 평가
4. 범용 수정에 필요한 실제 OS/OpenShell 격리·권한·검증 정책
5. 상시 관측, 핵심 API/여정 검사, 성능 탐지, 실제 버그 원본 적용의 서비스 검증·배포·회복 확인

현재는 로컬 및 비공개 소유자 시범이며 공개 다중 사용자 인증·인가를 제공하지 않습니다. 사용자 별도 대회 제출은 완료됐고, 이 저장소의 문안 초안은 실제 업로드본과 구분합니다.

사용법은 [가이드](guides/usage.md), 검사 명령은 [검증 절차](guides/verification.md), 단계별 과거 내용은 [보관된 구현 이력](archive/current-state-history.md)에 있습니다.

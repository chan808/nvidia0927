# 현재 구현과 목표 서비스의 간격

기준: 2026-09-28 저장소 코드·문서 확인. 이 문서는 **현재 사실**만 기록한다. 최신 상태를 확인할 때는 코드를 실행하고 결과를 날짜와 함께 갱신한다. 목표 설명은 [문서 지도](README.md)의 나머지 문서를 본다.

## 최신 A~D 메인 통합

A~D 세션은 모두 완료됐고 메인에서 통합 보완·전체 회귀·12건 평가·NAT 로컬 연결·검토용 묶음 재현을 진행했다. 최종 전체 회귀는 **499개 통과(174.74초)**이며, 최신 결과와 바로 실행할 명령은 [메인 통합 기록](main-integration.md)에 있다. 현재 일반 프로젝트 등록/공통 계약 판정, 검토 매뉴얼, 주 조사 계측이 연결돼 있다. 일반 프로젝트의 범용 수정·상시 감시·자동 배포는 구현하지 않았다. 실모델/OCR/실사건 검증과 비교 성능은 사용자 후속 검증을 기다린다.

**아래는 단계별 과거 기록이다. 병렬 진행 중이라는 문장이나 과거 회귀 수치는 최신 통합 상태로 사용하지 않는다.**

## 병렬 작업 중 메인 기반 점검

후속 [사전 통합 점검](preintegration-checks.md): A·D 원본은 편집하지 않고 이전 고정 사본의 사전 회귀와 기억/매뉴얼/재시작을 실행했다. 완료된 C에서 CLI 표시 정보 때문에 저장만 재시도가 거절되는 문제를 국소 수정했고, 새로운 저장 검사 6개·기반 10개·기존 C 47개가 통과했다. 이전 사본의 남은 실패 목록은 최종 통합용이며 현재 코드의 전체 통과/결함 수로 쓰지 않는다.

A~D 소유 작업은 병렬로 진행 중이며 인계 문서상 B/C는 완료됐다. **아래 249개 등 과거 회귀 기록은 당시 스냅샷 기준이고 새 전체 통합 통과가 아니다.** 메인은 소유 파일을 겹쳐 수정하지 않고 [로컬 검증 준비](local-verification.md)를 추가했다. 변경 포함 고정 사본에서 합성 프로필의 기억 끔/켬 CLI·SQLite 저장을 확인했고, 씨드의 ID 없는 접수→후보 확인→같은 사건 저장을 모델 0회로 확인했다. 새 기반 도구의 전용 검사 10개가 통과했다. 전체 회귀·실모델/실프로젝트·UI 화면·원본 적용·배포는 이번 작업에서 수행하지 않았다. 세부 출처는 [메인 인계](parallel/MAIN-foundation.md)에 있다.

## 최종 단계 전 재점검

[서비스 점검과 개선](pre-final-readiness.md)을 우선 읽는다. 첫 화면에서 러프한 제보→현재 개발 관측→후보 확인→실제 수정안→동일 검사·회귀→같은 SQLite·검토·후속 답변을 연결했다. 실제 브라우저의 씨드 한 건은 성공했다. 단일 프롬프트도 같은 요청 키 수정 방향을 맞혔다. 일반 조사에는 NVIDIA HTTP 500이 반복됐고, 개선한 최종 반환 스키마의 개별 호출만 성공했다. 일반 조사 전체 안정성과 실사건 게이트가 남아 **최종 제출 준비는 대기**다. 소규모 사전 비교를 수행했으며 아래 과거의 '비교 미시작'은 정식 최종 평가·제출에 한정해 읽는다.

이번 전체 회귀는 **249개 통과(기존 227+신규 22, 51.14초)**다. 서버 재시작 후 사건/후보 복원과 같은 사건의 후속 답변을 실제 화면에서 확인했다. 추가 외부 호출 16회는 모두 공개 합성 자료이며 실패를 포함한다. 자세한 증거와 미완료 게이트는 위 점검 문서에 있다.

## 구현된 것

- [루트 Streamlit 화면](../app.py)은 합성 trace ID 3개와 식별 실패 사례를 선택해 제보 텍스트의 일부 명시 항목을 관측과 비교한다. 제보가 없어도 관측된 합성 사건을 조사한다.
- [NVIDIA 직접 호출](../tracebridge/agent.py)은 Nemotron/NIM 한 번의 응답에서 API 계약·백엔드 오류·마이그레이션 상태의 읽기 도구를 선택한다. 최종 판정은 [규칙 코드](../tracebridge/triage.py)가 다시 조회한 자료로 만든다. 별도의 [NeMo Agent Toolkit 워크플로](../nat_workflow.yml)는 합성 자료의 읽기 도구를 최대 3회 반복한다.
- [제보 항목 대조](../tracebridge/claims.py)는 명시된 HTTP 상태·메서드·경로·`○○ API` 작업명과 확인 불가한 원인 추측을 일부 추출한다. 자유로운 자연어 전체를 검증하지 않는다.
- [증거 소스](../tracebridge/evidence.py)는 합성 fixture와 1 MB 이하 로컬 JSON 사건 묶음을 지원한다. 로컬 묶음은 오프라인 CLI에서만 판정한다.
- [샘플 재현](../tracebridge/repro.py)은 두 고정 pytest 템플릿을 샘플 앱·인메모리 SQLite에서 실행한다. 이는 대상 서비스 수정 검증이 아니다.
- [Agolive 페이지](../pages/1_Agolive_Investigation.py)는 로컬 코드와 제보자가 제공한 로그를 읽기 전용으로 검색한다. 로컬 Docker 로그는 사용자가 선택한 경우에만 조회한다. 별도 GPT 호출은 명시적 선택이며 [연결 문서](../AGOLIVE_INTEGRATION.md)에 제약이 기록돼 있다.
- 프로젝트용 [Skill](../skills/tracebridge-triage/SKILL.md)과 [SkillSpector 정적 검사 결과](../SKILL_SCAN_REPORT.md)가 있다.
- [제보 상관 CLI](../scripts/triage_report.py)는 사용자가 제공한 한 프로젝트의 로컬 JSON 사건 목록에서 요청 ID를 정확 조회하거나 시각·환경·메서드·경로로 단일 후보를 찾는다. 0건·복수 후보는 보류하고, 기존 판정기를 재사용해 안내·추가 조사·작업 후보로 라우팅한다. 목록은 합성 예시 또는 명시적으로 제공한 로컬 파일이며 실제 로그 플랫폼 연결이 아니다.
- [제보 에이전트 페이지](../pages/2_Report_Agent.py)와 [CLI](../scripts/investigate_report.py)는 자연어 지시·거친 증상·사진만 있는 제보를 받는다. 실제 NeMo Retriever OCR 호스팅 호출과 Nemotron Super의 코드 검색·로그 조회·구조화된 결과 반환을 합성 자료로 검증했다. 문구 없는 로딩 사진은 Nemotron Omni의 실제 호출로 보이는 증상만 해석한 뒤 원인 미확정·질문 상태로 반환하는 것까지 확인했다.
- [통합 접수](../tracebridge/report_agent.py)는 [공통 계약](../tracebridge/report_contract.py)으로 기존 `triage.analyze/route_verdict`와 연결됐다. 새 화면과 CLI에서 명확한 관측은 모델 없이 `GUIDANCE/WORK_CANDIDATE`, 단일 범위 후보나 서버 오류는 `INVESTIGATE`, 0/복수 후보·범위 부족은 `REQUEST_CONTEXT`로 구분한다. `--events` 또는 등록 로그 관측을 같은 판정기에 전달하며 규칙을 복사하지 않았다.
- [프로젝트 조사 도구](../tracebridge/report_agent.py)는 등록 파일/선택 Docker 로그의 발생 시각 ±5분·서비스·환경·프로젝트를 검사한다. 누락 필드는 미확인, 등록 범위는 `REGISTERED_SOURCE`로 표시한다. JSON/MDC 식별 필드만 사용하고 본문 ID·다른 요청 스택·시각/조사 모델이 만든 ID는 정확 상관으로 쓰지 않는다. 로그의 실제 응답 필드가 없으면 HTTP 상태를 추정하지 않는다.
- 여러 로그 소스에서 전달된 관측을 모두 합쳐 100개 한도와 완전성을 검사한다. 응답·서비스·환경·요청/계약 등의 충돌, 합산 한도 초과, 읽지 못한 소스 또는 중단된 수집은 `log_scope.aggregate`와 소스 기록에 남긴다. 불완전하거나 상충하는 목록으로 `GUIDANCE/WORK_CANDIDATE`를 확정하지 않는다. 등록 422 관측 100개 뒤에 제공 500 관측 1개가 오는 재현을 보류하도록 수정했다.
- 명시적인 사건 목록의 선택된 관측과 현재 로그도 같은 충돌 함수로 비교한다. 같은 프로젝트·요청 ID·서비스·환경과 선택 사건의 시각 ±5분에 속한 알려진 응답/요청 필드·계약/DTO 등만 비교한다. 목록 422와 현재 로그 500은 `NEEDS_CONTEXT/REQUEST_CONTEXT`로 보류하고 단일 `observed_status`와 제보 일치 판정을 확정하지 않는다. 양쪽 관측을 보존하고 충돌 출처·필드를 `log_scope.aggregate.conflicts`에 기록한다. 누락 값과 `[VALUE]` 같은 비식별화 값은 반대 증거가 아니며, 요청 필드 이름은 비교할 수 있다.
- 새 화면의 후속 답변과 CLI `--answer`는 같은 사건 ID를 유지해 자료를 다시 조회한다. 이전 관측·가설은 세션 `history`와 SQLite의 별도 실행으로 보존한다. CLI `--resume`은 최소 구조화 단서·자료 연결 해시·답변 횟수를 복원해 재시작 후 새 실행으로 답변한다. 원래 자유문/사진/OCR 본문은 복원하지 않는다.
- 재시작/후속 답변의 `오늘·어제`는 해당 메시지의 조사 함수 진입 시각을 UTC로 캡처하고 KST(+09:00) 날짜를 기준으로 해석한다. 최초 `session.received_at`은 보존하며 실행별 `message_received_at/relative_date_basis`만 추가한다. 명시 날짜/ISO 시각의 기존 우선순위는 유지한다. 가짜 시계로 9/28 접수 → 9/29 복원 후 `오늘 오전 10시`를 **9/29 10:00, REQUEST_CONTEXT/WAITING_CONTEXT, 응답 미확정**으로 확인했다. 9/28 자료는 제외했으며 `어제 오전 10시`는 9/28로 다시 조회해 안내했다. 새 테이블·원문 보관·실행 프레임워크는 추가하지 않았다.
- 화면의 새 **조사 시작**은 이전 활성 결과를 먼저 비운다. 빈 새 입력 등으로 실패해도 이전 사건의 판정을 새 결과로 표시하지 않는다. 같은 사건의 후속 답변이 실패하면 기존 활성 결과를 유지한다.
- 로컬 HEAD, 수동 SHA, 실행 컨테이너에서 읽은 revision label의 출처를 분리한다. 수동 `TRACEBRIDGE_DEPLOYED_SHA`만으로 배포 관측이 되지 않는다. 선택 Docker의 실행 상태/label만 읽는 어댑터는 구현·합성 검사했지만 실제 Agolive에서 배포 SHA를 관측하지 못했다.
- `run_status`는 라우팅과 별도로 완료·정보 대기·부분 실패·시간 초과·호출 예산 소진을 기록한다. 사진 OCR는 별도 입력 처리 서비스 호출이며 시각 해석은 모델 최대 4회에 포함된다. 실패해도 관측을 보존하며 지지된 가설을 원인 확정/수정 검증으로 표시하지 않는다.
- [작은 deadline helper](../tracebridge/deadline.py)로 조사 시간 예산의 남은 시간을 OCR·모델 HTTP와 Git/Docker 프로세스의 timeout에 전달한다. 만료 후 새 호출을 막고 `timeout_reasons`와 완료된 소스의 관측을 보존한다. 로그/코드 읽기에는 중간 만료 검사를 추가했다. HTTP timeout은 통신 단계별 제한이고 파일 읽기·이미지 처리는 강제 취소할 수 없어, 전체 실행의 엄격한 실시간 상한은 아니다. [통합 결과](stage-2-integration.md)에 적용 범위를 명시했다.
- 제출 묶음에 `pages`, `docs`, `examples`와 재현에 필요한 테스트 저장소 manifest가 포함되도록 수정했고 포함/제외 검사를 추가했다.
- [1·2단계 검토](stage-1-2-review.md)에서 성공/다른 서버 오류를 필드 차이만으로 작업 후보에 보내는 판정, 비정상 OCR 결과의 예외, 무관한 ID 본문/다른 요청 스택의 잘못된 로그 상관을 수정했다. 정상 400/422·마이그레이션 라우팅과 호출 예산·시간 초과 시 확보한 근거 보존을 회귀 검사했다.
- [SQLite 사건 기억](stage-3-memory.md)은 표준 sqlite3의 사건·실행·카드 3개 테이블과 FTS5로 구현했다. 기존 ID/revision을 재사용하며 후속 실행을 보존하고 동일 실행을 중복 저장하지 않는다. 다른 내용의 같은 ID/revision은 거절한다. 원본 제보/요청값/사진/로그/코드 대신 구분된 최소 기록·출처·해시를 남긴다. 기본 DB는 `output/tracebridge/incidents.sqlite3`이며 설정 가능하다. DB·임시 파일은 Git/패키지에서 제외한다.
- [내부 검토 CLI](../scripts/incident_memory.py)로 사건·실행·카드 조회와 승인·수정·반려를 한다. 검토 상태와 원인/수정 검증은 별개이며 미검토·반려 카드를 검색하지 않는다. 검토된 안내 또는 미확정 조사 단서만 같은 프로젝트의 정확 지문/FTS5로 최대 2개 반환한다. 과거 근거 참조에는 source run ID를 붙이며 현재 observations/evidence와 도구 권한을 늘리지 않는다.
- 현재 접수·조사에서 검색 결과를 과거 조사 단서로 전달하고 요청 연결·새 로그·현재 버전 출처를 재확인한다. 적중/검색 시간/현재 근거 참조를 기록한다. 합성 반복 422는 새 로그로 안내를 독립 판정했고 같은 경로의 현재 500/다른 예외는 과거 결론을 기각했다. 충돌·자료 부족은 기존 조사/보류를 유지했다. 빠른 응답·도구 호출 절감과 실사건 검증은 주장하지 않는다.
- 저장/검색 실패는 조사 결과와 분리해서 표시한다. 화면의 저장 재시도 버튼과 CLI `save --file`은 확보한 결과를 저장만 다시 하며 조사·모델·도구를 재실행하지 않는다. 조회·검토 기능은 로컬 파일 접근 권한을 가진 내부 담당자용이며 인증된 공개 서비스가 아니다.
- [4단계 격리 수정·검증](stage-4-change.md)은 `tracebridge-seed-signup`의 등록된 `SEEDED_DEVELOPMENT` 사례 1개만 A2로 허용한다. 기존 접수의 `WORK_CANDIDATE`를 저장된 최신 출처·완전한 정확 상관·dev 범위·정책/파일 해시와 대조하고 별도 사본을 만든다. 기존 NVIDIA 연결의 구조화된 키 이름 제안을 검사해 `client.py`의 반환 사전 키 리터럴만 바꾼다. 경로 이탈·링크/재분석 지점·hardlink·검사/설정 변경·잘못된 명령/근거/해시/크기는 거절한다. 임의 쉘·SQL·URL을 실행하지 않는다.
- 실제 Nemotron Super 호출은 2회였다. 첫 형식 거절을 별도 실패 기록으로 보존하고 새 씨드 사건에서 1회 호출로 `user_id→userId` 실제 후보 diff를 적용했다. 같은 입력·argv·환경/timeout의 관련 검사에서 종료 1/422 → 종료 0/201, 고정 회귀 3개 통과, 원본 snapshot 불변을 확인했다. `CHANGE_PREPARED/WAITING_REVIEW`, `candidate_fix_verified=true`는 씨드 사본 한정이다. 원본 적용·배포·서비스 회복·실사건 검증을 완료로 표시하지 않는다.
- 최소 `change_jobs` 1개 테이블과 schema 2로 작업/출처/새 실행을 연결하고 새 PENDING 카드를 기존 검토 절차에 둔다. 이전 실행·검토 카드를 보존하고 DB 실패는 별도 표시한다. [내부 CLI](../scripts/prepare_change.py)는 씨드 접수·작업 실행·조회·확보한 JSON 저장만 재시도를 제공한다. 기본 DB는 `output/changes/seed-incidents.sqlite3`이며 workspace 밖의 기록은 거절한다. 같은 출처는 다시 실행하지 않는다.
- 4단계의 실제 실행 제한은 등록된 신뢰 가능한 씨드 코드, 별도 사본, 검증된 키 리터럴 편집, Python `-I -B`, 허용 목록 환경과 고정 timeout이다. OS 파일/네트워크/자원 격리와 OpenShell 정책을 검증하지 않았으므로 임의 프로젝트 코드 실행의 안전성을 주장하지 않는다. 관련·회귀 실패/미재현/시간 초과/정책 위반은 성공으로 집계하지 않고 확보한 결과와 한계를 보존한다. `repro.py`의 환경 변수 샘플은 이번 완료 증거가 아니다.

## 구현되지 않았거나 실자료로 검증되지 않은 것

- 불특정 다수의 제보 접수, 조직/프로젝트별 인증·인가, 사용자별 사건 상태 및 알림, 다중 제보 중복 묶음.
- 실제 Agolive 실행 로그/APM과 배포 SHA의 실자료 연결·허가된 사건 검증, 운영/스테이징 DB의 읽기 전용 진단 연결. 등록 파일/선택 Docker 어댑터의 구현과 합성 검사를 실제 운영 연결로 집계하지 않는다.
- 범용 사용자 실수/실제 결함 분류, 중요도·소유자·작업 에이전트·보고 수신자의 정책 기반 라우팅.
- 인증된 공개 접수·다중 사용자 세션/검토, 임의 한국어의 완전한 구조화. 로컬 CLI 재시작 답변은 구현됐지만 원래 자유문은 보관하지 않는다. 현재는 알려진 작업명·간단한 한국어 날짜/시각/환경만 처리한다. 실제 사진 업로드+외부 API를 새 화면에서 다시 종단 검증하지 않았다.
- 실사건/실프로젝트의 재현·수정 diff/PR, 범용 코드 패치, CI·배포·배포 후 검증, 자동 해결/롤백. 등록된 씨드 1개의 검증된 후보 diff는 위 4단계의 제한 범위다.
- 다중 사용자 검토·조직별 인가·운영 보관/삭제 정책·범용 의미 검색과 제품 비교 지표. SQLite의 로컬 정확/FTS5 검색 지표를 운영 성능/절감 효과로 집계하지 않는다. NeMo Retriever OCR 외 Evaluator 등 다른 Microservice 통합은 없음.
- OpenShell 실행 격리, 전체 API/브라우저 능동 검사와 취약점 검증.

Agolive의 로컬 코드 검색 결과는 실제 배포 버전의 원인 확정이 아니다. README에 따르면 로컬 Docker가 꺼져 있었고 실제 OpenAI API 호출은 외부 코드 전송 승인 검토에서 거절돼 검증하지 못했다. 이 상태는 환경이 바뀌면 다시 확인한다. NAT 경로에는 간헐적 모델 시간 초과가 문서화돼 있다.

## 실행·검증 기준

설치는 [루트 README](../README.md)의 Python 3.12 절차를 따른다. 테스트는 `python -m pytest -q -p no:cacheprovider tests`다. 사건 기억의 기존 127+신규 30개로 만든 **157개 기준 검사를 이번 날짜 보완 전에도 통과**했다(26.67초). 기대값을 바꾸지 않고 가짜 시계 검사 13개를 추가해 **전체 170개가 정상 권한에서 통과**했다(29.31초). `git diff --check`도 통과했다. 날짜 보완 검사는 같은 날/다음 날 오늘·어제, DB 복원, 세션 자정, 명시 날짜/ISO, UTC/KST 경계, 함수 진입 시각, 이전 기록·자료 연결·답변 한도를 검사한다. 실제 날짜 대기·새 외부 모델 호출은 0회다. 제한 Windows 실행의 임시 폴더 접근 오류와 기능 실패를 구분했다. 정식 회귀 범위는 `tests/`이며 `generated/`의 수정 전 재현 산출물은 별도다. [2단계 통합 결과](stage-2-integration.md), [3단계 구현과 날짜 보완 재현](stage-3-memory.md), 기존 [NVIDIA 성공 기록](nvidia-validation.md)을 구분한다. 합성 검증은 실사건 자동 해결의 증거가 아니다.

현재 작업 트리에는 이 문서화 작업이 만든 변경 외의 수정이 있을 수 있다. 다음 작업자는 `git status`로 확인하고 기존 작업을 보존한다. 이 문서의 구현/미구현 표를 갱신하기 전에는 실제 호출·실행·결과를 확인한다.

4단계 작업 시작 시 기존 **170개**가 정상 권한에서 통과했다(29.34초). 신규 57개를 추가한 **전체 227개가 통과**했다(44.69초). 신규 모델/HTTP 검사는 TEST_DOUBLE이며 외부 호출 0회다. 별도 씨드 실제 모델 실행은 2회로 위 기록과 [4단계 결과](stage-4-change.md)에 구분한다. 기존 샘플 재현·날짜 검사의 기대값을 완화하지 않았다.

다른 세션으로 이어갈 때는 [인계 프롬프트](next-session-prompt.md)와 [4단계 결과](stage-4-change.md)를 함께 확인한다. 1단계는 로컬 JSON 재생, 2단계는 통합 구현·합성 검사, 3단계는 로컬 사건 기억·합성 검사, 4단계는 등록된 씨드 1개의 실제 모델 제안·격리 후보 검증을 완료했다. 직전 통합 작업에서 확인한 실제 저장소 HEAD는 `a25116f57c876d74c072b1151ee5a87494e2b11a`였고, backend는 콘솔 appender만 설정돼 있으며 등록 로그 파일이 없고 Docker daemon 연결이 실패했다. 이번 작업에서 실제 Agolive 연결을 다시 검증하지 않았으며 자료 확보 대기를 유지한다. 실제 실행 버전과 실사건 검증은 미완료다. 실행 로그 연결 정보와 화면·동작·시각·환경을 요청했으나 확보하지 못했다. 원본 Agolive 변경·병합·배포와 5단계 비교 평가·제출 작업은 수행하지 않았다. 기존 개발 서버가 살아 있다고 가정하지 않는다. 4단계 보고로 종료하며 후속 단계는 별도 요청 범위다.

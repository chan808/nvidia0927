이전 후속 구현은 **PC의 원본 적용 결과 보고와 적용 후 API 확인**이다. 검토된 후보의 diff·snapshot·정책·사건 revision을 대조한 멱등 보고, 신고 API 기대 결과와 별도 회귀 검사, 실제 로드한 snapshot 대응 헤더와 관측 기간을 연결했다. 성공은 `RESOLVED`, 실패는 `REOPENED`, 버전/응답 부족은 `OPEN`으로 저장하고 최신 기록에서 후속 조사를 이어간다. 공개 합성 프로젝트의 실제 파일 적용·HTTP, 중앙 SQLite/PostgreSQL, Streamlit AppTest로 확인했다. 자동 배포/롤백·브라우저 클릭 여정·daily 실제 장애 회복은 완료 범위가 아니다. [사용법](guides/project-recovery.md), [검증 기록](validation/project-recovery.md)을 확인한다.

이전 후속 구현은 **daily의 실제 개발 HTTP 요청 연결**이다. 프론트의 요청 ID·발생 시각·실패 메타데이터, backend의 제한된 JSONL·빌드 SHA/dirty 기록, 개발 로그인 한 endpoint의 소스 해시 대응 계약/DTO와 별도 서비스 health를 연결했다. 실제 HTTP 400 → 프론트 프록시 → TraceBridge API → 페어링 PC의 `EXACT_ID`와 모델 0회를 확인했다. 당시 전체 **650개 통과(175.86초)**에는 실제 PostgreSQL 30개가 포함된다. 기존 daily 데이터와 원본 적용 권한은 변경하지 않았다. 입력 검증 실패를 별도 개발 DB에서 재현한 것으로 실제 사용자 장애 해결과 구분한다. [사용법](guides/daily-observation.md), [검증·남은 범위](validation/daily-observation.md)를 확인한다.

그전 후속 구현은 **중앙 PostgreSQL + pgvector**, 작업/사건/카드/이력 통합 커밋, 동시 claim·epoch, 원 JSON/해시 보존 이전·역방향 export, 백그라운드 색인과 검색 쿼리 캐시/예산이다. 재검토에서 검색 중 정정·반려, 색인 중단·취소·만료, 프로젝트 참조, 잘못된 API 입력, 구버전 이전 검증, 사건 revision과 수정 이력 정렬을 보완했다. 최종 **632개 통과(198.93초)**에 실제 PostgreSQL 검사 30개가 포함된다. [운영 명령](guides/postgres-rag.md), [재검토·소스 해시·남은 조건](validation/postgres-rag-review.md), [초기 595개 검사](validation/postgres-rag.md)를 확인한다. 이전 고도화로 소유자 평가의 우선순위 큐·난이도별 조사 예산, 저장된 작업 목록/재열기·상태/모델 이력, 서비스·환경 범위 검색과 선택적 NIM 임베딩/RRF 검색을 추가했다. [당시 설정·평가·후속 순서](guides/operational-hardening.md)를 확인한다. 당시 자동 중요도/난이도 추정은 미구현이었으며 현재 공개 기본 서비스에서 관측 기반 잠정 평가를 제공한다. 임베딩 실호출·실사건 품질 향상은 별도 검증이다.

이전 SQLite 고도화 단계의 전체 회귀는 **579개 통과(108.56초)**다. 새 화면은 AppTest로 검증했으며 실제 브라우저의 이전 551개 GUI 시점 기록과 구분한다. [이번 검증·한계와 소스 해시](validation/operational-hardening.md)를 확인한다.

## 검증된 범위

[최종 통합 기록](validation/main-integration.md)에 전체 회귀 **499개 통과(174.74초)**와 패키징 보완 후 전용 검사 **27개 통과**가 기록돼 있습니다. 이 수치는 당시 코드의 실행 결과이며 문서 정리 작업의 새 전체 검사 결과가 아닙니다.

- CLI·화면 검사·SQLite·재시작·매뉴얼·정책·사본 검증·계측과 평가를 로컬에서 확인했습니다.
- 기존 Python 환경에서 압축 해제한 묶음의 재생을 확인했습니다. 새 환경 설치 성공은 별도입니다.
- NeMo Retriever OCR·Nemotron 실제 호출 증거는 [과거 NVIDIA 기록](validation/nvidia-validation.md)에 있습니다.
- 기억 켬/끔과 단일 프롬프트·일반 코딩 에이전트의 우위, 시간·토큰 절감은 입증하지 않았습니다.

## 남은 검증과 후속 기능

1. 허가된 실제 사건의 화면·동작·시각·환경을 실제 로그·실행 SHA·계약·호출자와 연결해 검증
2. 현재 조사 스키마의 실모델 반복·OCR·서빙 실패·NAT 종단 확인
3. 새 환경 의존성 설치와 같은 입력·권한·예산의 비교 평가
4. 범용 수정에 필요한 실제 OS/OpenShell 격리·권한·검증 정책
5. 상시 관측, 핵심 API/여정 검사, 성능 탐지, 실제 버그 원본 적용의 서비스 검증·배포·회복 확인
6. 공개 매뉴얼의 별도 승인·정제·철회와 챗봇, 범위/예산을 등록한 능동 점검. [후속 설계](design/basic-service.md#후속-확장)를 따른다.

관리·프로젝트 연결은 소유자 전용이며, 소유자가 켠 프로젝트는 제한된 공개 접수와 제보별 토큰 인가를 제공합니다. 팀·조직별 인증·인가는 후속 범위입니다. 사용자 별도 대회 제출은 완료됐고, 이 저장소의 문안 초안은 실제 업로드본과 구분합니다.

사용법은 [가이드](guides/usage.md), 검사 명령은 [검증 절차](guides/verification.md), 단계별 과거 내용은 [보관된 구현 이력](archive/current-state-history.md)에 있습니다.

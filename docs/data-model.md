# 자료 모델과 사건 기억

## 도메인 객체

| 객체 | 주요 필드 | 관계·규칙 |
| --- | --- | --- |
| `Organization` | id, 이름, 보관/접근 정책 | 프로젝트·사용자 권한의 상위 경계 |
| `Project` | id, 조직, 저장소/서비스 매핑, 환경 | 여러 서비스·저장소와 연결 가능 |
| `ProjectPolicyVersion` | 버전, 접수 정책, 자동화 수준, 경로/명령 허용 목록, 라우팅·통지 | 사건에서 평가에 사용한 정책 버전을 보존 |
| `Principal` | 사용자/서비스 계정 ID, 조직·프로젝트 역할 | 익명 제보는 제한된 임시 식별자로 관리 |
| `Report` | id, 원문, 제출자, 시각, 선택 첨부·캡처, 공개 범위 | 여러 Report가 하나의 Incident에 연결될 수 있음 |
| `Incident` | id, 프로젝트, 상태, 식별된 요청/서비스/환경, 중요도 | 사건의 현재 투영; 상태 변경은 `IncidentEvent`에 남김 |
| `IncidentEvent` | 순번, 사건 ID, 전/후 상태, 행위자, 근거/정책 ID, 시각 | append-only 감사·재생 기록 |
| `CandidateEvent` | 요청/trace ID, 시간, 서비스, 환경, 일치 기준 | 복수 후보와 기각 이유를 보존 |
| `ClaimCheck` | 주장 항목, 제보값, 관측값, 일치/모순/미확인, 근거 ID | 전체 자연어를 검증했다고 표시하지 않음 |
| `Evidence` | 종류, 원본 시스템 참조, 시각, 환경, 서비스, 배포 SHA, 상관 방식, 비식별화된 발췌/해시 | 원본 민감 자료는 기존 시스템에 보관. 참조 만료 가능 |
| `Hypothesis` | 설명, 지지·반대 근거 ID, 미확인 항목, 상태 | 모델 제안과 프로그램 판정 분리 |
| `AgentRun` | 역할, 모델·도구/정책 버전, 단계, 토큰, 시간, 도구 결과 참조 | 같은 결론까지의 조사 경로를 재생·평가 가능 |
| `WorkItem` | 유형, 책임 팀/사람, 중요도, 라우팅 근거, 상태 | 하나의 사건에서 프론트 수정·백엔드 수정·문서 개선이 별개로 생성 가능 |
| `ChangeSet` | 대상 저장소, 기준 SHA, diff/PR, 자동화 수준, 승인 | 원본 저장소 직접 변경 금지. 배포 결과는 별도 기록 |
| `Verification` | 재현 입력/명령 ID, 기준·후보·배포 버전, 실제 결과, 시간, 로그 참조 | 수정 전·후·배포 후를 구분 |
| `PolicyDecision` | 입력 요약, 정책 버전, 허용/거절/필요 승인, 이유 | 모델의 제안과 권한 판정 분리 |
| `Notification` | 수신자, 공개 범위, 채널, 템플릿, 시도/전달 상태 | 보고 대상별 내용 차등. 외부 전송 감사 |
| `IncidentMemory` | 정규화 지문, 짧은 증상·원인·조치, 버전, 검토 상태 | 유사 사건 검색 단서이며 현재 사건의 증거가 아님 |

객체 ID는 조직/프로젝트 범위와 함께 검사한다. 외부 제보자에게 내부 사건 ID나 저장소 경로를 그대로 노출하지 않는다. 타임스탬프는 UTC로 저장하고 화면에서 지역 시간을 표시한다. 동일 사건의 여러 제보와 여러 수정 시도를 덮어쓰지 않는다.

현재 [공통 접수 계약](../tracebridge/report_contract.py)은 선택적 `ReportContext`와 프로젝트·사건 ID·후보·상관·관측·사진 단서·가설·라우팅·질문·버전 출처·실행 상태를 반환한다. 세션 `revision/history/hypothesis_updates`에 더해 [로컬 SQLite](../tracebridge/incident_memory.py)가 사건·실행·카드 3개 테이블과 FTS5로 최소 기록을 보존한다. 위 전체 도메인 객체를 개별 테이블로 구현하지 않았다. 원문 제보/요청값·사진·로그/코드 대신 구분된 최소 기록·출처·해시와 구조화 접수 단서를 남긴다. 근거 ID는 각 `run_id`에 속하며 저장 가설은 `(run_id, evidence_id)`, 검색 카드는 `historical:<run_id>:<id>`로 참조한다. 이전 실행의 근거를 현재 가설에 자동 재사용하지 않는다. [실제 저장 구조·CLI·제약](stage-3-memory.md)을 현재 기준으로 삼는다.

## 증거와 판정의 연결

`Report`는 사람이 말한 내용을, `CandidateEvent`와 `Evidence`는 관측을, `Hypothesis`는 추론을, `Verification`은 실행 결과를 나타낸다. `ClaimCheck`는 항목별로 관측과 비교한다. 최종 요약 문장에는 관련 근거 또는 검증 ID를 연결한다. 로그에 예외명이 있다는 사실과 그 예외가 원인이라는 추론을 같은 상태로 저장하지 않는다.

사진 첨부는 파일 해시·형식·처리 상태와 함께 관리한다. OCR 문구는 서비스·모델·신뢰도·원본 이미지 해시를, 시각적 모델 해석은 모델·추론 여부를 남긴다. 둘 다 `Report`에서 파생된 단서이며 백엔드 `Evidence`와 다른 종류다. 현재 구현은 원본 사진의 자동 영속화를 제공하지 않는다.

각 증거는 최소한 `source_system`, `source_locator`, `collected_at`, `event_at`, `project/service/environment`, `deployed_version`(확인된 경우), `correlation_basis`, `sensitivity`, `redaction_applied`, `content_hash`를 가진다. 원본 참조가 나중에 만료되어도 사건 기록에는 당시 사용한 최소 발췌와 해시·조회 시각을 남긴다. 다른 사건의 증거를 근거 ID만 바꿔 재사용하지 않는다.

## 기억과 검색

사건 완료 또는 담당자 검토 후 짧은 `IncidentMemory` 카드를 만든다. 카드에는 프로젝트·서비스·경로, 실제 상태/오류 코드, 정규화한 예외/스택 지문, 증상 한 줄, 확인된 원인·반대 증거, 조치, 검증 범위, 배포/수정 SHA, 검토 상태를 둔다. 개인정보·원본 요청 본문·원본 로그는 카드에 넣지 않는다. `UNDETERMINED` 카드도 보존할 수 있지만 확인된 해결책처럼 순위를 높이지 않는다.

현재 실행 저장 시 `PENDING` 초안을 만들고 담당자가 `APPROVED/EDITED/REJECTED`로 검토한다. 검색에는 승인/수정 검토된 카드만 포함한다. `GUIDANCE`와 `UNCONFIRMED`를 구분하며 검토 상태를 `cause_confirmed/fix_applied/fix_verified`와 분리한다. 검토 수정은 카드 문구/인덱스만 바꾸고 원 실행·검증 상태를 바꾸지 않는다. `COMPLETED`·검토 승인·지지된 가설은 해결/수정 검증이 아니다. 충돌·시간 초과·미확정 실행을 해결 카드로 자동 승격하지 않는다.

검색 순서는 같은 프로젝트의 정확한 오류 코드/경로/지문 → SQLite FTS5 전문 검색 → 필요성이 입증되면 임베딩 유사도다. Markdown은 읽기·내보내기 형식으로 유지할 수 있다. 벡터 DB는 필수 저장소가 아니다. 과거 카드가 맞아 보이더라도 현재 요청 ID, 새 로그, 배포 SHA를 다시 확인한다. 피드백(원인 수용/반려·수정 성공/실패)은 카드의 신뢰도와 검색 순위에 반영하되 예전 결론을 사실로 승격시키지 않는다.

현재는 정확/FTS5만 구현했고 프로젝트 scope를 프로그램과 매개변수화 SQL로 검사해 최대 2개를 반환한다. 검색 자체의 모델 호출은 없다. 접수/조사에서 카드를 과거 단서로 전달하며 현재 요청·로그·버전 출처와 비교한 상태/근거 참조, 적중 수·검색 시간을 실행 기록에 남긴다. 다른 현재 근거는 과거 결론을 기각하고 부족/충돌은 기존 조사/보류를 유지한다. 인과관계·실사건·절감 효과나 운영 보관/삭제 정책은 이 구현으로 입증하지 않았다.

## 보관과 삭제

조직/프로젝트 정책에서 원본 첨부, 비식별화한 발췌, 사건 카드, 감사 이벤트의 보관 기간을 따로 정한다. 원본 로그는 가능하면 기존 관측 시스템에 두고 링크·해시만 저장한다. 사용자의 삭제 요청이나 원본 참조 만료 후에는 재현 가능 범위를 사건에 표시한다. 학습 데이터나 평가셋으로 재사용할 때는 별도의 허용 범위와 비식별화가 필요하다. 데이터 접근·변경·내보내기도 감사 이벤트로 남긴다.

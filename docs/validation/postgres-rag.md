# PostgreSQL·RAG 기반 구현 검증

2026-09-29, Windows amd64 / Python 3.12.7. **전체 595개 통과, 174.73초.** 기존 기능과 새 PostgreSQL 통합 15개를 같은 검사에서 실행했다. [메타데이터·소스 해시](postgres-rag.json), [운영 명령](../guides/postgres-rag.md)을 함께 확인한다.

## 환경과 실행 증거

- 공식 EDB PostgreSQL **18.6** 바이너리를 워크스페이스 `output/pg-validation/`에 압축 해제했다. 공식 pgvector **v0.8.6** 소스를 MSVC로 빌드해 이 런타임에만 설치했다.
- 별도 클러스터는 `127.0.0.1:55432`에만 연결했다. 각 검사는 고유한 `tracebridge_test_<UUID>` DB를 만들고 그 DB만 정리했다. 기존 서비스 DB·Docker 설정을 초기화하지 않았다.
- Docker Desktop은 시작 과정에서 자체 오류로 종료돼 새 Compose의 Linux 실행 검증에 사용하지 못했다. 엔진 설정 변경이나 공장 초기화는 하지 않았다.
- `pip check` 통과. 현 환경에서 wheel 빌드 후 두 Alembic revision·env·저장소·이전 모듈 포함을 확인했다. 새 환경 설치 성공을 뜻하지 않는다.
- PostgreSQL/RAG overlay의 `docker compose ... --profile rag config --quiet`는 종료 코드 0이었다. 이미지 기동·HTTPS·Linux 복원 검사는 수행하지 않았다.

전체 로그는 로컬 `output/pg-validation/isolated-final-regression.txt`에 있다. Windows sandbox의 파일 mode 제약 때문에 승인된 검사 실행과 새로운 임시 디렉터리를 사용했다. 임베딩·채팅은 doubles이며 새 유료/실제 NIM 호출은 없다.

## 실제 PostgreSQL에서 확인한 것

| 검사 | 결과 |
| --- | --- |
| 조사와 후보 | HTTP 접수 → 등록 코드/로그 조사 → 사본 전후/회귀 검사 → 중앙 결과와 이력 저장 |
| 동시 claim | 같은 실행기의 병렬 8회 요청 중 작업 하나만 실행 상태가 됨 |
| 원자성 | 완료 저장에 오류를 넣으면 사건·실행·카드·완료 이벤트까지 롤백; PC outbox 재전송으로 저장 |
| 임대/복구 | 만료가 다음 작업을 막고 복구 epoch가 증가; 이전 epoch 갱신 거부 |
| 검색 범위 | 프로젝트·서비스·환경·검토를 SQL에서 제한; 한국어 FTS와 실제 pgvector 연산 |
| 정정/반려 | 벡터 호출 중 변경된 카드 결과를 저장하지 않고 즉시 검색에서 제외 |
| 검색 실패 | 제공자 오류에도 키워드 결과 유지 |
| 예산/캐시 | 같은 쿼리 벡터 재사용·새 쿼리 2회 제한; 현재 승인 상태로 카드 조회 |
| 불명확한 결과 | 쿼리 timeout 영속화·같은 쿼리 재전송 거부·본문 없는 검색 이력 |
| 비동기 색인 | HTTP 전송 호출 없이 작업 ID 저장; 별도 실행기의 lease와 결과 기록 |
| 색인 lease | 만료된 작업의 벡터 저장 거부·소유자 재시도로 진행 |
| 차원 | 같은 identity의 다른 차원 거부 |
| 이전/역방향 | 원 JSON·해시·이력 ID·불명확한 모델 상태·벡터 JSON 비교; 새 상태 변경까지 SQLite export에 포함 |
| 이전 거부 | 쓰기 중지 미확인·활성 작업·비어 있지 않은 대상 거부 |
| 이전 실패 | FK 오류 시 모든 대상 테이블이 비어 있는 상태로 롤백 |

이전 시험의 private 입력은 저장된 최소 JSON에서 제거된다. 따라서 원 입력 해시는 최소 JSON으로 재계산할 수 없다. 원 해시·문자열 보존과 source SQLite의 비교 전후 일치를 확인했다.

## 보존한 자료와 남은 조건

운영 중앙 서버의 두 파일을 전환하거나 기존 로컬 DB를 재색인하지 않았다. 로컬 사건 **2,891건**, 실행 **3,120건**을 보존했다. 이 건수는 품질 표본이나 실제 장애 해결 건수가 아니다.

기존 테스트 일부가 기본 로컬 DB를 사용해 사건 95건·실행 101건을 추가한 것을 발견했다. 101개 카드가 모두 `PENDING`이고 새 95개 사건에만 속하며 기존 실행·수정 작업과 참조가 겹치지 않음을 확인했다. 전체를 비공개 백업하고 ID·원 JSON 해시를 비교해 **해당 테스트 기록만** `output/pg-validation/isolated-test-additions.sqlite3`로 분리했다. 기존 사건 목록과 건수를 복원했고 기존 **7개 논리 테이블의 모든 남겨 둔 행·해시가 처리 전후 일치**하며 FK 검사도 통과했다.

`tests/conftest.py`에서 기본 저장소를 각 테스트 임시 경로로 격리한 뒤 **595개 전체 검사**를 다시 통과했다. 격리 후 검사 전후에도 운영 DB의 7개 테이블이 백업과 일치해 새 기록이 생기지 않았음을 확인했다. 감사·백업·분리 증거는 로컬 `pre-isolation-record-audit.json`, `local-journal-isolation-verification.json`, `test-record-separation-verification.json`에 보존한다.

독립 Vector DB는 추가하지 않았다. 네이티브 정확 검색을 구현했고 ANN 인덱스·리랭커·형태소 모델 비교는 후속이다. 합성 임베딩으로 계약을 확인했으므로 한국어 NIM 품질·지연·절감·실서비스 진단 성공률을 주장하지 않는다.

실제 사건의 증상·기대한 동작·발생 시각과 로그·실행 SHA가 필요하다. 그 사건의 조사·재현·승인·적용 후 여정 검증은 남아 있다. 팀 인증/RLS, 관측 기반 자동 중요도·난이도 제안, 자동 배포·서비스 회복도 후속이다.

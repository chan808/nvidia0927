## 목표와 작업 지시

TraceBridge의 현재 구현을 보존하고 이번에 사용자가 요청한 단계만 진행해줘. **2단계 실자료 연결은 자료 확보 대기이고 3단계 사건 기억의 로컬 구현·합성 검증은 완료됐다. 4단계 수정과 5단계 비교 평가·제출은 별도 명시 요청이 있을 때만 시작해.** 코드·실행 결과로 입증되지 않은 기능을 완료로 표시하지 마. 외부 연결 정보가 부족하면 필요한 사항을 짧게 묻고 요청 범위 안에서 그 정보에 의존하지 않는 작업을 진행해.

제품의 목표는 사용자의 오류 제보를 현재 관측과 대조해 안내, 정보 요청, 조사, 작업 후보로 구분하고, 허용된 작업을 실제로 수행·검증한 뒤 결과를 기억해 다음 유사 제보를 더 빨리 처리하는 것이다. 사용자는 기술자가 아닐 수 있고 **자연어 지시, 거친 증상 한 줄, 사진만 있는 입력**도 허용해야 한다. HTTP 메서드·API 경로·SQL·SHA·trace ID를 필수 입력으로 강요하지 마. 필요한 질문은 어떤 화면/동작인지, 대략 언제인지, 화면 오류 문구 같은 쉬운 한국어로 해.

## 현재 구현과 검증된 범위

### 1단계 — 로컬 JSON 재생 범위에서 완료

- `tracebridge/report_intake.py`, `scripts/triage_report.py`, `examples/report_events.json`, `tests/test_report_intake.py`.
- 한 프로젝트, 1 MB/최대 100개 사건. 요청 ID 정확 일치 또는 시간 ±5분·환경·메서드·경로의 단일 후보를 찾는다. 0건/복수/ID 충돌은 보류한다. 시각 기반 후보는 확정 사건이 아니다.
- 제보의 “500”을 검색 조건으로 쓰지 않는다. 실제 422 입력 검증은 `GUIDANCE`, 관측된 400/422의 호출자 필드 불일치나 500의 마이그레이션 불일치는 `WORK_CANDIDATE`, 불확실하면 `INVESTIGATE/REQUEST_CONTEXT`.
- `WORK_CANDIDATE`는 실제 작업 실행/수정 완료가 아니다. 4xx만으로 사용자 책임을 확정하지 않는다.

### 2단계 — 통합 구현/합성 검증 완료, 실자료 게이트 미완료

- `tracebridge/nemo_ocr.py`, `tracebridge/report_agent.py`, `pages/2_Report_Agent.py`, `scripts/investigate_report.py`.
- PNG/JPEG 8 MB·2천만 픽셀, 메타데이터 제거·전송 크기 제한. OCR 신뢰도 0.75 미만은 검색/ID 연결에 쓰지 않는다. OCR의 requestId 라벨 I/l/1 혼동만 보정하고 ID 값은 고치지 않는다. 원본 사진은 자동 저장하지 않는다.
- NeMo OCR로 문구를 읽고 문구가 거의 없으면 Omni로 보이는 화면 증상을 해석한다. 사진/OCR/시각 해석은 제보 단서이며 서버 원인 근거가 아니다.
- Nemotron이 `search_code`, `find_logs`, `get_version`을 선택하고 `finish_investigation`으로 결과를 낸다. 최대 모델 4회(Vision 포함), 읽기 도구 6회, 코드 6개·로그 20줄. OCR은 별도 서비스 호출이다.
- 등록된 로컬 파일/제공 로그/선택한 Docker 로그만 읽는다. 모델이 경로·ID·임의 쉘/SQL을 만들어 실행하지 못한다. 명시 ID 필드 또는 Agolive MDC 형식의 정확 ID만 로그 상관에 사용한다. 모델 검색어가 같은 사건을 만들어내지 못한다.
- `SUPPORTED_HYPOTHESIS`는 범위/ID가 맞는 로그와 코드의 **가설**이다. 버전 label 상관을 검사해도 원인의 인과관계·실행 바이너리·재현·수정 확인을 뜻하지 않는다. 배포 미확인은 `LOG_CANDIDATE/CODE_ONLY`, 관측 불일치/반대 인용은 `CONTESTED_HYPOTHESIS`로 낮춘다.
- `report_contract.py`의 공통 결과와 `triage.analyze/route_verdict`를 사용해 네 라우팅을 구분한다. 명확한 관측은 모델 0회, 모호한 사건은 제한 조사다. 화면/CLI 답변은 같은 사건을 재조회하고 이전 자료·반증 결과를 세션 history에 보존한다. 라우팅과 다섯 조사 종료 상태는 별개다.
- 로컬 HEAD·수동 SHA·실행 컨테이너 label을 분리한다. `TRACEBRIDGE_DEPLOYED_SHA`만으로 배포 관측이 되지 않는다. 파일/제공/Docker 로그의 시각·서비스·환경·프로젝트 필터는 구현됐으며 누락 필드는 미확인, 등록 값은 `REGISTERED_SOURCE`다. 실제 Agolive 배포 관측은 없다.
- 실제 Agolive 오프라인 확인: HEAD `a25116f57c87`, 검색 대상 변경 없음, ROOM_FULL 코드 3개, 실행 로그 0개, 원인 보류. backend는 콘솔 로그만 설정됐고 Docker daemon은 연결되지 않았다. 실제 로그 파일/APM 위치와 사건 시각·환경이 필요하다.
- 실제 NVIDIA 검증은 합성 자료만 사용했다. 성공 결과는 `output/validation/nemo_ocr.json`, `report_agent.json`, **`rough_report_super.json`**, `visual_report_agent.json`이며 다른 실험 파일에는 실패도 있다. 파일이 존재한다고 성공으로 집계하지 마.
- 새 조사 도구는 기존 NAT 워크플로에 등록되지 않았다. 기존 `nat_workflow.yml`/`nat_plugin.py`는 합성 데모용이다. 새 경로에서 NAT를 사용한다면 기존 도구/실행 경로를 얇게 연결하고, 중복 조사 엔진은 만들지 마. 그렇지 않으면 현재 NAT 사용 범위를 정확히 문서화해.

직전 검토의 50개 검사를 보존하고 통합 후 **87개가 정상 권한에서 통과**했다. 범위 불일치/누락, 사진·시각 모델 생성 ID, 수동/실행 SHA 분리, 도구/모델 실패, 후속 답변·반증, 같은 화면/CLI의 네 라우팅을 검사했다. 실서비스 정확도/원인 확인의 증거는 아니다. 새 NVIDIA 호출 없이 기존 성공 기록을 재사용했다.

## 이어서 수행할 작업과 완료 조건

### A. 남은 2단계 실자료 게이트부터

1. 기존 공통 계약·판정·화면/CLI와 회귀 검사를 먼저 재확인해. 통합을 다시 구현하거나 판정 규칙을 복사하지 마.
2. 읽기 허가된 실제 로그 파일 또는 사용 가능한 로컬 Docker, 제보의 화면·동작·대략적인 시각·환경을 확보해. 기존 파일/Docker 연결과 관리자 서비스·환경·시간대 등록을 사용해. 자료가 없으면 필요한 연결 정보만 짧게 요청하고 합성/실자료 검증 상태를 분리해.
3. 로그의 누락 필드·본문 ID·복수 후보를 확인된 같은 사건으로 승격하지 마. 현재 실행 버전은 실행 서비스에서 읽은 출처가 있을 때만 관측으로 기록해. 수동 SHA·사건 snapshot만 있으면 배포 미확인이다.
4. 확보한 허가 사건 하나를 읽기 전용으로 조사해. 현재 근거에 따라 기존 가설을 재검토하고 관측·가설·실행 종료·미확인을 기록해. 실제 자료의 외부 전송은 별도 허용 범위를 확인하며, 기존 합성 NVIDIA 성공을 불필요하게 반복하지 마.
5. 실자료 게이트 결과를 문서에 갱신한 뒤 사용자가 요청한 범위대로 보고해. 2단계만 요청한 세션에서는 아래 사건 기억·수정·평가 구현을 시작하지 마.

완료 증거: 같은 접수 화면/CLI에서 실제 관측에 따른 안내·조사·보류·작업 후보가 구분되고, 로그 범위와 배포 출처가 기록된다. ID 없이도 조사/쉬운 질문으로 이어지며 잘못 연결된 사건을 확정하지 않는다. 합성 통과와 실제 사건 검증은 별도로 표시한다.

### B. 3단계 — SQLite 사건 기억 (완료 상태 확인용)

[실제 저장 구조·검토 CLI·157개 회귀·합성 재현](stage-3-memory.md)을 확인해. 아래 항목은 완료한 로컬 범위의 기준이며 운영/실사건 검증 완료를 뜻하지 않는다.

1. 표준 `sqlite3`와 FTS5로 시작해. 최소 사건/실행 기록, 검토된 카드, 검색 인덱스 정도면 충분하다. 전체 제품 문서의 모든 객체를 개별 테이블로 구현하지 마. Markdown 내보내기는 필요할 때 추가해.
2. 원문 관측·모델 가설·실행 결과·사람 검토·수정 검증을 섞지 마. 실패/미확정 실행도 기록할 수 있지만 해결된 기억 카드로 자동 승격하지 마. 최소한 출처·프로젝트·환경·시각·코드/배포 버전·검토/검증 범위를 보존해.
3. 같은 프로젝트의 오류 코드/경로/지문 정확 검색 → FTS5 순서로 최대 2개 카드를 가져와. 카드가 현재 사건의 근거 ID를 대신하거나 읽기/변경 권한을 바꾸지 못하게 해. 현재 로그·버전·상관을 재확인한 뒤 응답해.
4. 재시작 후 기록 유지, 검토/반려 반영, 프로젝트 범위 검색, 반복 제보와 **비슷하지만 현재 원인이 다른 제보**를 검증해. 한국어 FTS 검색 품질은 측정하고 부족한 경우부터 개선해. 벡터 DB는 검색 누락의 실제 근거가 생기기 전엔 추가하지 마.

완료 증거: 두 번째 유사 제보에서 검토된 카드를 찾고, 현재 사건이 다른 원인이면 이전 결론을 기각한다. 빠른 응답/조회 절감은 측정 결과로만 주장한다.

### C. 4단계 — 한 가지 격리 수정·검증

1. 허가된 대상 프로젝트와 확인 가능한 결함 한 가지를 선택해. 현재 원본 Agolive를 직접 수정하지 마. 기준 커밋과 필요한 작업 트리 상태를 명시해 workspace 안의 격리 사본에서 작업해. 필요한 외부 권한은 실제 도구 권한/프로젝트 정책에 따라 처리해.
2. 기존 `tracebridge/repro.py`의 샘플 재현을 실제 대상 프로젝트 수정 검증으로 계산하지 마. 모델의 요청을 정책이 허용한 작업자에게 전달하는 작은 실행 경로를 만들어. 작업 역할을 모델 프로세스 여러 개로 나누는 것은 필수가 아니다.
3. 대상 경로·변경 크기·고정 검사 명령 ID·시간 제한을 관리자가 지정해. 모델이 생성한 임의 쉘/SQL을 실행하지 마. 임의 프로젝트 코드를 안전하게 실행했다고 주장하려면 실제 격리 근거가 필요하다. OpenShell은 실제 연결·정책 적용·실행 검증한 경우에만 사용 기술로 기록해.
4. 수정 전 관련 검사 실패 → 후보 diff → **같은 검사**와 회귀 통과를 기록해. 검사 자체를 완화하거나 무관한 실패를 성공으로 계산하지 마. 회귀 실패/시간 초과/증거 부족에서는 변경을 검토 대기로 남기고 성공으로 표시하지 마.
5. 원본/후보 버전, diff, 명령 ID, 종료 코드, 결과·한계를 사건에 연결해. 최소 목표는 `CHANGE_PREPARED/WAITING_REVIEW`다. 자동 병합·배포·운영 DB 변경·외부 알림은 이번 범위에 추가하지 마.

완료 증거: 실제 대상 파일에 대한 검토 가능한 수정 diff와 수정 전후 동일 검사·회귀 기록. 실자료가 부족해 씨드 결함을 쓰면 분명히 표시하고 실제 운영 장애 해결로 설명하지 마.

### D. 5단계 — 비교 평가와 제출 준비

1. 같은 사건·코드·로그·자료 접근 권한으로 (a) 규칙 파이프라인, (b) 단순 프롬프트/수동 코딩 에이전트 처리, (c) TraceBridge를 비교해. 구현/실행하지 않은 기준군 숫자를 만들지 마. 수동 비교가 필요하면 실행 절차·측정 양식을 만들고 실제 측정 전 상태를 명시해.
2. 보고 500/실제 422, 실제 백엔드 실패, 복수/없는 후보, 사진만 있는 입력, 무관한 로그, 로컬/배포 불일치, 모델 시간 초과, 과거 카드와 다른 현재 원인, 허용되지 않은 작업, 수정 후 회귀 실패를 포함해.
3. 잘못된 확정·올바른 보류·라우팅·검증된 조치, 소요 시간·질문 수·모델/도구 호출·토큰·기억 검색 효과를 기록해. 작은 합성 세트의 결과를 일반 정확도로 확대하지 마.
4. 깨끗한 환경에서 재현할 입력·버전·설치·실행 명령과 데모 순서를 정리해. 실제 프로젝트가 없어도 테스트 저장소로 실행하는 Streamlit 설정과 CLI 예시를 제공해. `scripts/package_submission.py`의 포함 파일·문서 링크·비밀 제외·압축 해제 후 검사도 확인해.
5. 기존 성공 호출 원시 기록은 로컬 검증 증거다. 공개 가능한 합성 실행 기록만 선별·비식별화해서 재현 묶음에 넣어. 실제 사진 원본·비밀·운영 로그·허가되지 않은 코드가 제출물에 들어가지 않게 해. 제출 파일 생성과 외부 제출은 구분해.

완료 증거: 실제 비교 결과, 동작하는 데모, 재현 패키지와 NeMo 사용의 코드·공식 제품 분류·실제 호출 기록이 일치한다. 아직 없는 실사건 연결/검증은 제출 문안에도 미완료로 남긴다.

## 실행 명령과 모델 설정

```powershell
# 기준 테스트
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider tests

# 1단계 합성 재생
.\.venv\Scripts\python.exe -m scripts.triage_report --events examples/report_events.json --report '회원가입 API에서 500 requestId=claim-003'

# 2단계 오프라인 접수
.\.venv\Scripts\python.exe -m scripts.investigate_report --report '방에 들어가면 계속 튕겨요. 확인해줘.' --repo tests/fixtures/agolive_repo --logs-file examples/agolive_error.log

# 합성 자료만 외부로 전송하는 실제 NVIDIA 재검증(필요할 때만)
.\.venv\Scripts\python.exe -m scripts.smoke_ocr
.\.venv\Scripts\python.exe -m scripts.investigate_report --image output/validation/room_error.png --repo tests/fixtures/agolive_repo --logs-file examples/agolive_error.log --live --output output/validation/report_agent.json

# 실제 Agolive 연결 없이 접수 화면을 실행
$env:TRACEBRIDGE_AGOLIVE_REPO = (Resolve-Path tests/fixtures/agolive_repo).Path
.\.venv\Scripts\python.exe -m streamlit run app.py
```

- `NVIDIA_API_KEY`: 기존 root `.env`에서 사용. 키 값 출력 금지.
- 새 조사 모델: `TRACEBRIDGE_INVESTIGATION_MODEL`, 기본 `nvidia/nemotron-3-super-120b-a12b`.
- Vision: `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`.
- OCR: `nvidia/nemotron-ocr-v2`, `https://ai.api.nvidia.com/v1/cv/nvidia/nemotron-ocr-v2`.
- `TRACEBRIDGE_LOG_FILE`: 등록 로컬 로그. `TRACEBRIDGE_DEPLOYED_SHA`: 수동 설정값.
- 자기 호스팅 OCR은 `TRACEBRIDGE_OCR_URL`/`TRACEBRIDGE_OCR_API_KEY`를 사용하며 NVIDIA 키를 다른 호스트에 보내지 않는다.
- 기존 합성 화면의 `NVIDIA_MODEL`은 새 조사 모델 설정과 별개다.
- 호스팅은 모델 목록에 있어도 404/410/시간 초과가 있었고 초기 Lightning/Omni 응답 형식 실패가 있었다. 현재 성공 기록을 우선 사용하되 모델 변경 시 실제 제한된 호출로 확인해. 무한 재시도하지 마.

## 작업 방식과 최종 보고

먼저 코드/상태/테스트를 확인하고 가장 작은 연결부터 구현해. 단계별로 완료 조건을 만족하면 `docs/current-state.md`, `competition-mvp.md`와 관련 문서를 실제 결과로 갱신해. 새 기능 때문에 생기는 구체적인 위험을 검증하는 테스트를 추가하되 반복적인 형식 검사나 과도한 전체 재시험은 피하고, 필요한 게이트가 통과하면 다음 단계로 진행해.

다중 조직 인증 시스템, 자동 운영 배포, 큐/플랫폼 재구축, 범용 작업 에이전트, GPU 학습, 벡터 DB를 처음부터 만들지 마. 지금 필요한 저장·검색·조사·검증 흐름을 연결하는 데 집중해.

마지막에는 단계별 완료/미완료, 실제 연결 여부, 변경 파일, 실행/검증 결과, 재현 명령, 아직 필요한 외부 정보를 짧게 정리해. 조사됨·원인 확인됨·수정 검증됨·배포됨·서비스 회복됨을 서로 다른 상태로 보고해.

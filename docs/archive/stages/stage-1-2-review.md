# 1·2단계 검토 결과

> 과거 기록입니다. 당시 계획·검사·제약을 보존하며, 현재 상태는 [구현 상태](../../current-state.md)를 기준으로 확인하세요.

검토일: 2026-09-28. 기준은 [대회용 최소 구현 순서](../plans/competition-mvp.md)다. [제품 전체 로드맵](../../design/roadmap.md)의 번호와 혼동하지 않는다. 코드·회귀 검사·저장된 실제 NVIDIA 호출 결과·현재 로컬 연결 상태를 대조했다. 이번 검토에서 새로운 외부 모델 호출이나 3~5단계 구현은 수행하지 않았다.

**후속 갱신:** 이 문서는 통합 전 검토 기록이다. 이후 [접수·판정 통합](stage-2-integration.md)에서 공통 계약·네 라우팅·같은 세션 답변·등록 로그 범위·버전 출처·종료 상태를 구현하고 총 87개 회귀 검사를 통과했다. 실제 실행 로그/배포 관측·실사건 검증은 여전히 미완료다. 아래 독립 경로/범위 필터 미구현 설명과 50개 수치는 **직전 검토 당시**의 사실이며 최신 상태는 [현재 상태](../../current-state.md)를 따른다.

## 판정

| 범위 | 판정 | 확인한 근거와 한계 |
| --- | --- | --- |
| 1단계: 제보와 관측 연결 | **계획한 로컬 JSON 재생 범위에서 완료** | 정확 ID, 환경 불일치, ID 충돌, 0/복수 후보 보류, 단일 시각 후보의 임시 연결, 관측 상태에 따른 라우팅을 검사했다. 실제 로그/APM 상관과 범용 결함 분류는 포함하지 않는다. |
| 2단계: 자연어·사진 접수 | **구현 및 합성 자료의 실제 API 연동 확인** | 거친 글, 사진만 있는 입력, 글 없는 로딩 사진을 처리한다. NeMo OCR·Nemotron Super·Omni의 성공 결과 파일을 확인했다. Streamlit 자동 검사는 글 접수의 오프라인 경로다. 실제 사진 API 검증은 CLI 경로이며 UI에서 실제 사진을 업로드한 종단 검증은 별도다. |
| 2단계: 프로젝트 조사 전체 | **미완료** | 실제 Agolive 코드를 읽을 수 있으나 현재 실행 로그와 배포 관측이 없다. 새 화면은 1단계 판정기와 독립된 경로다. 조사·추가 질문만 반환하며 안내/작업 후보의 공통 라우팅은 아직 연결되지 않았다. |
| 대회가 요구한 문제 해결 | **아직 입증되지 않음** | 합성 사건의 도구 선택·접수는 확인했지만 실사건의 조사→검토 가능한 수정→검증→기억 재사용은 남아 있다. |

따라서 “1·2단계 모두 완료, 다음은 저장소만 추가”로 인계하면 안 된다. **2단계 연결을 마무리하고 실제 연결의 증거를 확보하는 작업이 먼저다.**

## 검토 중 재현하고 수정한 결함

| 결함 | 수정 | 회귀 근거 |
| --- | --- | --- |
| `user_id`/`userId` 차이가 있으면 실제 HTTP 200이나 다른 서버 오류도 곧바로 호출자 수정 후보가 됨 | `triage.py`에서 이 작업 후보 판정은 관측된 400/422에 한정한다. 구조적 차이는 증거로 보존하고 성공 응답·5xx는 추가 조사한다. 5xx의 백엔드 예외 조회가 먼저 차단되지 않는다. | `test_report_intake.py`: HTTP 200, HTTP 500+TimeoutError에서 `INVESTIGATE`. 기존 422·마이그레이션 라우팅도 유지. |
| OCR의 `text_prediction=null/배열`이 전체 조사에 예외를 발생시킴. boolean 신뢰도는 숫자로 인정되고 큰 정수는 변환 오류를 일으킴 | `nemo_ocr.py`에서 잘못된 감지 항목을 건너뛰고 boolean·범위 밖 신뢰도를 제외한다. 유효한 다른 문구는 유지한다. | `test_nemo_ocr.py`: 비정상 항목·boolean·큰 정수 검사. `test_report_agent.py`: OCR이 유효한 글을 못 읽고 Vision이 실패해도 사용자가 함께 쓴 글로 조사를 계속함. |
| 로그 아무 위치의 ID 값이나 다른 요청의 들여쓴 로그가 동일 사건 근거로 섞임 | `project_sources.py`에서 명시 ID 필드 또는 Agolive의 시간/레벨/MDC 접두사로만 정확 상관한다. MDC가 우선이며 `?`인 경우 메시지 속 ID를 대신 쓰지 않는다. 다른 ID가 있는 줄에서 스택 연속 상관을 끊는다. | `test_project_investigation.py`: 무관한 본문·다른 ID·MDC 누락·다른 요청 스택은 제외, 정상 필드/JSONL 모양/MDC는 유지. |

이는 지원하는 입력 형식의 회귀 방지다. 임의 로그 형식 전체의 사건 식별, JSONL의 모든 중첩 필드 해석, 원인 정확성까지 보장하지 않는다.

## 통합 전 검토에서 남긴 간격

1. **공통 접수·판정 경로:** `report_intake.py`의 규칙 라우팅과 `report_agent.py`의 조사 결과를 이어야 한다. 현재는 프로젝트 식별 필드도 `project_id`와 `project`로 다르며 관측 응답·제보 대조가 새 화면으로 이어지지 않는다. 단순 사건은 모델 없이 안내/작업 후보로, 모호한 사건은 제한된 조사/질문으로 보내는 작은 공통 계약이 필요하다.
2. **현재 사건의 범위:** 등록 로그 파일은 마지막 300 KB와 문구/ID로 검색한다. 파일/제공 로그에는 발생 시각 필터와 서비스·환경 검증이 없다. Docker의 `--since`만 최근 조회다. ID 없는 로그는 항상 후보다. 같은 ID라는 사실도 배포 코드·현재 시점·실제 원인을 모두 확인했다는 뜻은 아니다.
3. **배포와 소스 근거:** `TRACEBRIDGE_DEPLOYED_SHA`는 수동 설정이다. 실행 중인 서비스에서 수집한 SHA가 아니므로 배포 관측으로 승격하지 않는다. 코드와 로그를 함께 인용한 `SUPPORTED_HYPOTHESIS`도 원인 확인/수정 확인이 아니다. 근거 ID 검사에는 인용 내용과 원인의 의미적 일치 검증이 없다.
4. **조사 종료와 후속 질문:** 라우팅과 실행 완료/부분 실패/예산 소진을 구분할 명시 상태가 필요하다. 현재 후속 질문 응답을 같은 사건에 합치는 지속 흐름도 없다. 일부 실제 결과는 영어였으므로 사용자 요약·질문의 한국어 표시도 점검한다.
5. **실사건 검증과 반증:** 실제 로그 소스·발생 동작·시간·환경이 확보되면 하나의 허가된 사건을 끝까지 조사한다. 지금의 실제 실행 기록은 검색 실패 후 재검색을 보여주지만, 반대 증거로 원인 가설을 폐기하는 사례를 충분히 입증하지는 않는다.

새 조사 도구는 아직 `nat_workflow.yml`/`nat_plugin.py`에 등록되지 않았다. 해당 NAT 경로는 기존 합성 사례 전용이다. 코드 변경·검증 작업자, 사건 저장/검색, 피드백, 비교 평가는 모두 후속 단계다.

## 대회 기술 조건 재확인

[NVIDIA NeMo 공식 허브](https://docs.nvidia.com/nemo/)는 Microservices 항목에 Retriever를 포함하고, [Retriever 소개](https://docs.nvidia.com/nemo/retriever/)는 OCR NIM을 구성 서비스로 소개한다. [Image OCR 공식 설명](https://docs.nvidia.com/nim/ingestion/image-ocr/latest/overview.html)도 NeMo Retriever OCR 마이크로서비스로 명시한다. 사진 접수에 연결한 실제 호스팅 OCR 호출은 이 제품군 활용의 근거다. 자체 GPU 배포·NeMo Framework 설치·전체 플랫폼 설치를 수행한 것은 아니다.

사진 속 **NeMo Framework 또는 NeMo Microservices 활용, 재현 가능한 코드, 작동하는 데모, 스스로 판단하고 실행해 문제 해결**을 계속 기준으로 삼는다. OCR 활용 근거가 있다고 서비스의 문제 해결 능력까지 완료된 것은 아니다. 활용 도구 목록 전체를 필수라고 단정하거나 아직 연결하지 않은 OpenShell·새 NAT 경로를 사용했다고 발표하지 않는다.

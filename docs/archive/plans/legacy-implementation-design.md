# TraceBridge 구현 설계

> 과거 기록입니다. 당시 계획·검사·제약을 보존하며, 현재 상태는 [구현 상태](../../current-state.md)를 기준으로 확인하세요.

TraceBridge는 API 오류 제보 또는 제보 없는 백엔드 사건을 조사합니다. 기존 NVIDIA 화면은 **합성 사고 3개와 식별 실패 1개**를 다루고, 오프라인 CLI는 로컬 JSON 사건 묶음을 읽습니다. 별도 [Agolive 제보 조사](../../guides/agolive.md)는 실제 Agolive 로컬 저장소와 사용자가 선택한 로그를 읽기 전용으로 검색합니다. 운영 로그·배포 버전에는 연결되지 않았습니다. 다음 단계는 [구현 계획](initial-implementation-plan.md)에 정리했습니다.

## 조사 흐름

1. `EvidenceSource`가 `trace_id`로 해당 요청·응답을 찾습니다. 기존 fixture와 로컬 JSON 묶음이 이 계약을 구현합니다. 요청이 없으면 원인 추측과 NVIDIA 모델 호출을 생략합니다.
2. 합성 자료의 라이브 경로는 NVIDIA Nemotron NIM에 관측된 trace를 주고, API 계약·백엔드 오류·마이그레이션 상태 중 조회할 읽기 전용 도구를 선택하게 합니다. 직접 호출 경로의 모델 요청은 최대 1회, 모델이 요청할 수 있는 도구는 최대 3회입니다. 로컬 JSON은 오프라인에서만 분석합니다.
3. Python 검증기는 제보가 있으면 명시된 HTTP 상태·메서드·경로·`○○ API` 작업명을 항목별로 대조합니다. 두 가지 알려진 불일치를 검사하고, 그 외 5xx 예외는 유형 단서만 표시합니다. 모델이 필수 근거를 빠뜨렸거나 잘못된 trace ID로 조회를 시도하면 올바른 trace의 읽기 전용 근거를 보완합니다.
4. 최종 판정과 사용자 요약은 검증기의 결과에서 만듭니다. 모델이 작성한 자유 형식 문장은 사용자에게 판정으로 표시하지 않습니다.
5. 지원하는 유형에서만 고정된 pytest 템플릿을 만들고, 별도 프로세스의 샘플 앱·인메모리 SQLite에서 실패와 후보 수정 후 통과를 비교합니다.

## 판정

| 값 | 현재 의미 |
| --- | --- |
| `claim_items` | 추출한 항목마다 `MATCHED` / `CONTRADICTED` / `UNVERIFIABLE`. 해석하지 못한 자연어 전체는 검사하지 않음. |
| `claim_status` | 추출 항목의 집계: `MATCHED` / `CONTRADICTED` / `PARTIAL` / `UNVERIFIABLE`. 제보가 없으면 `NOT_PROVIDED`. |
| `finding_status` | 알려진 불일치 확인은 `CONFIRMED_MISMATCH`, 필수 필드 누락에 따른 400/422 관측은 `OBSERVED_VALIDATION`, 그 외는 `INCONCLUSIVE`. |
| `repro_status` | 조사 단계에서는 `NOT_ATTEMPTED`. UI에서 테스트를 실행한 뒤 실패/통과 결과를 별도로 표시. |

현재 확인 가능한 유형은 요청의 `user_id`와 계약·DTO의 `userId` 차이, 그리고 `phone` 컬럼 오류와 V11/V12 마이그레이션 불일치입니다. `claim-003`은 보고된 500을 관측된 422로 정정하는 반례입니다.

## 실행 경계

- 모델 도구는 합성 자료를 읽는 `get_contract`, `get_backend_evidence`, `get_migration_state`뿐입니다. 코드 실행, 임의 파일 읽기, DB 변경 도구는 제공하지 않습니다. 로컬 JSON은 라이브 모델 경로에서 사용할 수 없습니다.
- 도구 인자의 trace ID는 현재 요청과 일치해야 합니다. 백엔드 로그는 해당 사례에서 최대 50줄만 반환합니다.
- 재현 파일은 두 개의 고정 템플릿 중 하나입니다. `generated/`의 테스트만 실행하며, 테스트 프로세스에는 NVIDIA API 키를 전달하지 않습니다.
- 후보 수정 후 통과는 **샘플 코드와 격리 DB**에 관한 결과입니다. 실제 서비스 수정 완료의 증거가 아닙니다.
- 로컬 JSON은 1 MB 이하, 로그 최대 200줄로 제한합니다. CLI에서 파일을 읽어 현재 프로세스에서 판정하며 모델로 전송하거나 테스트를 실행하지 않습니다. 예외 종류 외에 원인을 확정하지 않습니다.
- 별도 NeMo Agent Toolkit 경로는 같은 읽기 전용 자료를 조사하지만, 호스팅 모델 지연으로 간헐적으로 시간 초과가 나며 핵심 UI 경로가 아닙니다. OpenShell은 현재 재현 실행에 연결되지 않았습니다.

실서비스 연동에는 trace ID 전파, 원본 API 계약·로그·마이그레이션 상태의 읽기 전용 어댑터, 개인정보 제거, 실행 격리와 별도 검증이 필요합니다.

## Agolive 제보 조사 경계

- 기본 실행은 로컬 코드 검색이다. 네 서비스 소스의 선별된 줄과 manifest 위치, 로컬 Git 커밋을 근거로 보여준다. 실제 배포 코드와 같다고 가정하지 않는다.
- 사용자가 로그를 제공하거나 로컬 Docker 조회를 선택해야 로그를 읽는다. `requestId` 일치가 없으면 같은 사건의 로그라고 확정하지 않는다.
- GPT는 기본 꺼짐이다. 사용자가 전송을 선택하면 Agolive의 기존 OpenAI 키·모델 설정을 사용해 검색어와 구조화된 원인 후보를 생성한다. 근거 ID가 없는 모델 주장은 확인된 근거로 취급하지 않는다.
- 이 경로는 대상 코드 수정, 테스트 실행, 취약점 탐색을 수행하지 않는다. 근거 있는 원인 후보와 후보 조치도 재현 전에는 확정하지 않는다.

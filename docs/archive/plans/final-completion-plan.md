# TraceBridge 남은 작업 최종 설계

> 과거 기록입니다. 당시 계획·검사·제약을 보존하며, 현재 상태는 [구현 상태](../../current-state.md)를 기준으로 확인하세요.

기준: 2026-09-28. 이 문서는 **앞으로 수행할 작업과 완료 기준**이다. 이번 설계 작업에서 서비스 코드 수정, 회귀 재실행, 실제 프로젝트 조사, 외부 모델 호출은 하지 않았다. 기존 1~4단계의 구현·실행 기록은 [최종 단계 전 점검](../pre-final-readiness.md)에 보존한다.

## 1. 최종 목표와 제출 범위

**한 프로젝트에 연결된 에이전트가 거친 자연어·사진 제보를 현재 관측에 연결하고, 필요한 조사를 선택하며, 허용된 수정안을 같은 검사로 검증하고, 검토된 사건 지식을 다음 조사에 재사용한다.**

대회용 완료 범위는 한 프로젝트의 핵심 사용자 흐름 하나, 비교 가능한 문제 유형 몇 가지, 등록된 수정 작업 한 종류다. 조사 도구는 그 프로젝트의 다른 증상에도 사용할 수 있게 만든다. 수정 범위를 넓히는 것은 실제 정책·검증 능력이 확보된 만큼만 진행한다.

제보자는 채팅과 사진으로 시작한다. 요청 ID·메서드·경로·SHA를 필수로 입력하지 않는다. 내부 담당자가 프로젝트의 코드·로그·계약·실행 버전·검증 명령을 연결해 둔다. 후보가 여러 개면 사용자의 동작 확인을 받아 연결하고, 현재 자료를 다시 조회한다.

최종 작업 결과는 기본적으로 `CHANGE_PREPARED / WAITING_REVIEW`다. 후보 사본의 검증과 원본 적용·서비스 회복은 별개다. 자동 배포, 전체 API 관리, 상시 모니터링, 다중 조직, 벡터 DB, 모델 재학습은 이후 확장 범위로 둔다.

## 2. 검토 의견의 반영 결정

| 의견 | 결정 |
| --- | --- |
| 로그 바이트·줄 절단 뒤 잘못된 확정 | 최우선 수정. 수집 범위의 완전성과 화면·모델 발췌 제한을 분리한다 |
| `user_id/userId`, `phone`에 묶인 판정 | 공통 계약 검사와 근거 기반 책임 조사로 변경한다. 고정 사례는 회귀·시연 자료로 남긴다 |
| 500 제보의 오류와 실제 가입 실패를 구분 | 보고 사실·현재 관측·가설·책임·조치·종료 결과를 분리한다 |
| 실제 프로젝트 연결이 Agolive 구조에 고정 | 한 프로젝트 설정 파일과 작은 소스 인터페이스를 도입한다. 범용 플러그인 플랫폼은 만들지 않는다 |
| 자가학습·기억 효과가 미입증 | 검토된 사건 지식으로 설명하고, 기억 켬/끔 비교로 효과를 측정한다 |
| 역할 이름만 반환하는 라우팅 | 조사 도구와 등록된 수정 작업자를 실제로 호출하는 경로를 연결한다. 추가 역할은 설명만 반환한다 |
| NAT가 별도 fixture 경로 | 주 조사에 쓰는 공용 함수의 도구·모델·시간 기록을 계측하는 최소 연결을 한다 |
| 사본 실행을 OS 격리처럼 설명 | 등록된 신뢰 가능한 대상과 고정 검사의 제한을 유지한다. 임의 코드 실행을 허용하려면 실제 격리 검증을 선행한다 |
| 모든 NVIDIA 제품 도입 | 실제 역할이 있는 구성만 사용한다. 트랙·예선의 별도 필수 조건은 각각 확인한다 |
| 전체 프로젝트를 완벽히 관리 | 현재 제출 범위에서 제외하고, 핵심 여정·API 검사와 관측 기반 사건 생성으로 후속 로드맵을 적는다 |

사용자가 전달한 247개 통과 기록과 현재 점검 문서의 249개 기록은 서로 다른 스냅샷의 기록이다. 이번 작업의 새 통과 기록으로 합치지 않는다. 테스트 개수만으로 아래 결함이 해결됐다고 판단하지 않는다.

## 3. 유지할 최소 구조

`채팅/사진 → 사건 연결 → 현재 자료와 계약 검사 → 필요 시 적응형 조사 → 정책 검사 → 수정 작업자 → 같은 재현·회귀 → SQLite·검토 카드·매뉴얼`

사건 기억은 조사 앞과 조사 중에 조회할 수 있다. 과거 카드는 현재 관측으로 승격되지 않는다. 결정적인 계약 검사는 코드가 수행하고, 모델은 모호한 단서 해석·다음 조회·가설 수정·수정 제안을 담당한다. 정책과 검증기는 모델 밖에서 작동한다.

- **소스 결과:** 자료와 함께 조회 조건, 출처, 버전, 수집 완료 여부, 절단·누락·시간 초과 이유를 전달한다.
- **판정:** 보고한 HTTP 상태의 진위와 실제 증상·제품 결함 여부를 각각 설명한다. 책임 미확정 상태를 허용한다.
- **실행:** 조사와 수정 제안을 분리한다. 수정 작업은 현재 사건의 근거와 등록된 정책을 다시 확인한 뒤 실행한다.
- **지식:** 승인·원인 확인·후보 검증·원본 적용·회복 확인을 각각 기록한다.
- **관측:** 조사·OCR·수정 제안의 호출량과 도구 결과·실행 시간을 구분한다. 사용량 미반환은 0으로 집계하지 않는다.

기존 SQLite, Streamlit, NIM 클라이언트, 정책 작업자를 재사용한다. 새로운 서버·작업 큐·에이전트 군을 기본 의존성으로 추가하지 않는다.

## 4. 남은 6단계

### R1. 수집 완전성과 판정의 신뢰성 복구

**목표:** 읽지 못한 자료를 충분히 확인한 것으로 취급하지 않는다.

주요 대상은 `project_sources.py`, `report_agent.py`, `report_intake.py`와 관련 회귀 검사다.

1. 작업 시작 시 HEAD·미커밋/미추적 변경·관련 파일 해시·실행 환경을 기록해 검증 기준을 고정한다. 기존 변경을 보존한다.
2. 파일 읽기, 제공 로그, Docker 결과의 바이트·줄·관측 수 제한 및 시간 초과를 소스 결과부터 최종 결과·저장·화면까지 전달한다. 상위 함수에서 이미 절단했다면 하위 함수가 이를 잃지 않아야 한다.
3. 요청 ID·프로젝트·서비스·환경·요청 시간 범위로 관측을 수집한 뒤 표시할 발췌를 제한한다. 시간·메모리 예산 안에서 스트리밍으로 검사하고, 검사 범위를 끝내지 못하면 부분 결과로 남긴다. 한도를 단순히 높여 해결하지 않는다.
4. 수집 완전성은 등록된 자료의 해당 조회 범위에 대한 사실이다. 자료 부재, 부분 조회, 충돌 부재를 서로 구분한다. 여러 소스의 누락도 합산 상태에 반영한다.
5. 범위가 불완전하거나 관측이 상충하면 확정형 `GUIDANCE / WORK_CANDIDATE`와 수정 작업 진입을 막는다. 확보한 관측은 유지하고 추가 자료 요청·조사를 허용한다. 이미 발견한 충돌은 발췌에서 빠져도 보존한다.
6. Docker의 고정 최근 조회·`--tail`·stdout 절단을 요청 시간 범위 및 완료 상태와 연결한다. 지난 사건 조회가 안 되면 미지원/미완료로 남긴다.

**완료 기준**

- 짧은 500/422 충돌, 약 481KB 중간 채움, 짧은 줄 6,000개 재현에서 잘못된 422 확정이 모두 사라진다. 전체 범위를 확인하면 충돌로 보류하고, 끝까지 읽지 못하면 불완전성으로 보류한다.
- 정상적인 완전 자료의 안내·작업 후보 경로는 유지된다. 사건 연결·개인정보 제외·이전 결과·후속 답변·시간 예산 회귀도 유지된다.
- 새/기존 회귀 검사와 `git diff --check`가 통과한다. 이 단계는 외부 모델 없이 완료한다.
- 소스 결과와 최종 화면/저장 기록이 같은 완전성·충돌 상태를 나타낸다.

### R2. 샘플에 묶이지 않는 판정과 프로젝트 근거 연결

**목표:** 필드 이름을 바꿔도 동일한 근거에 동일한 판단을 하고, 실제 계약을 읽을 수 있다.

1. 프로젝트 설정 파일 하나에 프로젝트 ID, 서비스/환경, 코드 검색 루트, 로그 소스, API 계약 경로, 실행 버전 관측 방법, 등록된 작업 정책을 정의한다. 시크릿은 설정 파일에 넣지 않는다. Agolive와 씨드는 같은 인터페이스의 어댑터로 유지한다.
2. 초기 연결 범위는 로컬 JSON/구조화 로그와 등록된 OpenAPI 파일이다. 실제 대상에 필요한 경우 계약 endpoint나 한 가지 추가 로그 어댑터만 붙인다. 로그 안에 계약 snapshot이 항상 있다는 전제를 제거한다.
3. 계약의 필수 필드·관측된 필드·검증 가능한 타입 차이를 공통 코드로 계산한다. 비식별화된 실제 값이나 미관측 타입은 추정해 확정하지 않는다.
4. `account_id/accountId` 같은 표기 유사성은 후보다. 현재 계약·요청 생성 코드·서버 DTO·실행 버전 근거로 변경 책임을 조사한다. 계약 차이만으로 이름을 바꾸지 않는다.
5. 필수 입력 누락의 관측과 제품이 정상이라는 결론을 구분한다. 호출자의 요청 생성 결함이 있거나 책임이 불분명하면 안내로 조사를 종료하지 않는다.
6. `phone` 문자열은 일반 원인 규칙에서 제거한다. 실제 마이그레이션 상태 연결이 없는 경우 DB 관련 가설로만 남긴다. DB 변경 작업자는 이번에 추가하지 않는다.
7. 거친 자연어는 기존 빠른 추출을 유지하고, 의미가 모호할 때만 구조화된 모델 추출을 선택한다. 모델이 만든 ID·환경·시각은 현재 근거가 아니다. 모호한 동작에는 결정에 필요한 질문 한두 개를 제시한다.

**완료 기준**

- 기존 키 오류와 이름을 바꾼 계약 오류에서 같은 구조적 차이를 찾고, 코드 근거가 없으면 작업 대상을 확정하지 않는다.
- 수동 입력 누락, 클라이언트 직렬화 결함, 현재 5xx, 계약 부재, 로컬 코드/실행 SHA 불일치를 구분한다.
- Agolive 폴더명이 없는 별도 작은 프로젝트도 설정으로 조회한다. 필요한 소스가 없으면 그 사실을 표시한다.
- “500”을 잘못 보고했지만 가입 실패와 호출자 결함은 남아 있는 사례가 정상 서비스로 종결되지 않는다.
- 설정·소스 자료가 수정 실행 권한을 자체 부여하지 못한다.

### R3. 적응형 조사와 실제 작업 호출 연결

**목표:** 근거에 따라 다음 행동이 바뀌고, 허용된 작업자가 실제 수정안과 검사 결과를 만든다.

1. 주 조사에 계약 조회 도구를 연결하고 기존 코드·로그·버전 조회를 공용 소스 함수로 유지한다. 새 최종 스키마로 조회부터 종료까지 확인한다.
2. 조사 기록에 가설, 구별할 조회의 목적, 선택한 도구/검색 조건, 새 관측, 다음 판단을 남긴다. 비공개 사고 과정의 전문을 요구하지 않고 짧은 근거 설명을 기록한다.
3. 검색 실패나 반증 뒤 검색어·조회 대상·가설을 바꾸는 사건을 검증한다. 근거 부족·자료 충돌·예산 만료에는 중단하고 현재 결과를 보존한다.
4. 프론트/백엔드 책임, 조사/수정 권한, 모델 자원은 구분한다. 이번 실제 작업 역할은 기존 호출자 수정 작업자 한 종류로 연결한다. 지원하지 않는 역할은 미지원 작업으로 표시한다.
5. 작업자는 등록된 파일 범위·기준 해시·편집 한도·고정 검사·시간 제한을 재확인한다. 현재 근거가 바뀌면 오래된 작업 후보를 실행하지 않는다. 같은 사건의 후속 답변이나 저장 재시도가 수정 실행을 중복시키지 않는다.
6. 선택한 실제 개발 대상에서 필요한 최소 수정 범위만 정책으로 등록한다. 임의 프로젝트·임의 명령 실행은 열지 않는다. 모델이 생성하는 일반 코드를 실행하도록 범위를 넓힐 경우 OpenShell 등 실제 실행 격리를 먼저 검증한다. 사본·`-I`·timeout만으로 OS 격리라고 설명하지 않는다.
7. NAT는 동일한 주 조사 함수와 도구·모델 이벤트를 계측하는 최소 어댑터로 연결한다. 별도 fixture 결과를 주 서비스의 결과로 계산하지 않는다. 기존 루프를 전면 재작성하지 않는다.

**완료 기준**

- 서로 다른 조사 사건에서 각각 독립된 반복 실행이 조회→관측→최종 반환까지 성공한다. 중간 도구 하나의 성공으로 전체 성공을 대신하지 않는다.
- 한 사건은 실제 모델이 초기 조회 실패/반증 후 다음 조회를 바꾸는 기록을 남긴다. 고정된 시연 분기를 넣지 않는다.
- 외부 모델 장애는 내부 판정 오류와 구분되고, 무한 재시도·허위 해결 성공이 없다. 실제 외부 호출 검증은 사용자가 실검증을 진행할 수 있을 때 수행한다.
- 허용된 후보는 수정 전 관련 실패→실제 diff→동일 검사 성공→회귀 통과를 기록한다. 검사·정답·기대값을 바꿔 성공시키지 않는다.
- 원본·재현 명령·정책 해시 보존, 거절·미재현·회귀 실패·timeout·재시작·저장 재시도 검사를 통과한다.
- NAT의 실제 기록과 서비스 실행 ID·호출 수·종료 상태가 일치한다. 실패하면 NAT 주 흐름 연결은 미완료로 남긴다.

### R4. 사건 기억을 검토 가능한 프로젝트 매뉴얼로 연결

**목표:** 기록이 쌓이는 것을 넘어, 다음 조사에서 확인 순서와 조치에 사용할 수 있다.

1. 기존 카드에 증상/관측 특징, 적용 프로젝트·환경·동작·버전, 확인 순서, 반증 조건, 조치, 검증 결과, 출처 실행, 마지막 확인 상태를 최소한으로 보강한다.
2. 검토 상태와 원인/수정/적용 검증 상태를 구분한다. 후보 사본에서만 성공한 사례는 “수정안 검증”으로 표시한다. 승인됐다는 이유로 해결 완료 매뉴얼을 만들지 않는다.
3. 현재 버전·조건이 다르거나 자료가 미확인인 카드는 조사 단서로 낮춘다. 잘못된 카드의 정정·폐기와 유효하지 않은 적용 조건을 보존한다.
4. 매뉴얼 화면 또는 Markdown 내보내기는 검토 카드로부터 생성한다. 근거·적용 조건·한계가 빠진 새 결론을 생성하지 않는다. 조사 에이전트는 이 확인 순서를 단서로 읽고 현재 자료를 확인한다. 매뉴얼이 편집/실행 권한을 부여하지 않는다.
5. 기억 켬/끔 실행 옵션을 추가하고 초기 DB 상태를 고정할 수 있게 한다. 아직 검토되지 않은 현재 평가 결과가 다음 평가 입력으로 섞이지 않게 한다.

**완료 기준**

- 같은 문제의 반복 제보에서 과거 확인 순서를 사용하되 현재 관측을 재검증한다.
- 같은 경로·상태라도 다른 예외/버전/현재 충돌이면 과거 원인과 조치를 기각하거나 보류한다.
- 폐기 카드, 검토 변경, DB 재연결, 사건 이어보기, 과거·현재 근거 ID 분리가 유지된다.
- 매뉴얼의 모든 조치·검증 표시에 출처가 있다. 모델 재학습이나 자동 정확도 향상으로 설명하지 않는다.
- 현재 정확/FTS 검색을 사용한다. 임베딩은 표현 차이로 인한 검색 누락이 평가에서 확인된 경우의 후속 선택이다.

### R5. 실제 프로젝트와 동일 조건 비교 검증

**목표:** 제한된 씨드 밖에서 가치와 실패 범위를 측정한다. 실검증이 가능한 시점에 진행한다.

실제 개발 프로젝트 한 곳의 핵심 동작 하나를 선택한다. 서비스·환경·발생 시각·현재 로그·실행 SHA·해당 계약·코드·검증 명령을 연결한다. 자연 발생 결함과 통제해서 주입한 결함은 기록·발표에서 구분한다. 접근 자료가 없으면 실사건 검증 완료로 표시하지 않는다.

**고정 평가 세트: 6개 유형, 유형당 2개 변형으로 총 12건**

| 유형 | 확인할 행동 |
| --- | --- |
| 정상적인 입력 검증 | 사용자 입력 누락과 클라이언트가 정상 입력을 잘못 전송한 경우를 구분 |
| 계약/호출자 결함 | 기존 키 오류와 이름을 바꾼 오류에서 근거에 따른 같은 판단 |
| 모호한 자연어·사진 | ID 없는 제보를 후보에 연결하고 필요한 확인만 요청; 보고한 상태와 실제 증상 분리 |
| 불완전·충돌 자료 | 바이트/줄/수집 예산 절단·관측 충돌에서 잘못 확정하지 않음 |
| 비슷한 과거, 다른 현재 | 같은 경로·상태의 다른 예외와 버전 변화에서 과거 처방을 재검증 |
| 적응형 조사·실행 실패 | 초기 조회 실패/반증 후 방향 변경; 미재현·회귀 실패·서빙 장애에서 적절히 중단 |

실제 사건 또는 실제 개발 실행에 연결한 사례는 위 세트에 출처를 붙여 포함한다. 나머지 재생·합성 사례도 출처를 표시한다. 세트 구성과 기대 판단은 비교를 시작하기 전에 고정한다. 로그 절단의 세 독립 재현과 세부 회귀 검사는 별도로 모두 유지한다.

**비교 조건**

- 규칙 파이프라인: 사건 연결·확정·보류 능력 비교.
- 단일 프롬프트: 같은 현재 자료로 판단/제안의 품질 비교. 답변만 하는 조건의 수정 실행 시간은 비교하지 않는다.
- 개발자+일반 코딩 에이전트: 같은 코드·로그·계약 접근, 허용 명령, 재현·회귀 검사로 조치까지 비교. 사람의 자료 수집·전달·검토 시간을 실제로 기록한다.
- TraceBridge 기억 끔/켬: 같은 현재 사건·초기 검토 카드·설정·예산에서 기억 사용 여부만 바꾼다. 규칙만으로 이미 끝난 사례에서 기억 효과를 주장하지 않는다.

측정은 사건 연결, 올바른 라우팅/보류, 잘못된 원인·해결 확정, 불필요한 수정, 같은 검사로 검증된 조치, 질문 수, 사람의 수작업, 모델/도구 호출·토큰·전체 시간이다. 서로 다른 수행 범위의 시간은 같은 지표로 섞지 않는다.

**완료 기준**

- 한 실제 개발 프로젝트에서 거친 접수→현재 근거→조사→검토 가능한 조치/보류→저장 흐름을 확인한다. 수정 후보의 사본 검증과 실제 서비스 회복은 별도 결과다.
- 12건의 기대/실제/출처/실패 이유와 비교 원자료를 남긴다. 핵심 실제 모델 사건은 반복 실행 결과와 서빙 실패도 함께 보고한다.
- 안전·진실성 게이트인 자료 충돌, 불완전성, 버전 불일치, 검증 실패에서 허위 확정이 없어야 한다. 이는 고정 세트 결과이며 보편적인 정확도 보장이 아니다.
- 기억 사용의 이득·동률·악화를 그대로 보고한다. 이득이 없으면 효율 우위 문구를 제거하고 원인을 분석한다.
- 확인된 사용자 가치와 남은 일반화 한계를 구분한다. 경쟁 서비스 대비 독창성은 검증한 경험으로 설명한다.

### R6. 제출본·시연·대회 증빙 완성

**목표:** 다른 환경에서도 같은 서비스와 검증 흐름을 재현하고, 실제 사용 범위를 정확히 설명한다.

1. 신청 초안을 자연어·사진·현재 관측·적응형 조사·후보 diff·검증·기억 재사용 중심으로 갱신한다. 구현과 검증이 끝난 부분만 완료로 표시한다.
2. 실제 통과한 의존성 버전·Python·실행 환경을 고정하고, 제출 ZIP/저장소의 새 환경 설치·CLI·UI·재시작을 확인한다. 생성 산출물·기존 DB·시크릿에 의존하지 않도록 한다.
3. 오프라인 재생과 실제 NVIDIA 호출 모드를 구분한다. 실패를 보존한 녹화·재생은 예비 증거로 제공하고 실제 호출처럼 표시하지 않는다.
4. 공개 예시는 비식별/합성 자료로 묶고, 실제 코드·로그의 공개 범위는 별도로 확인한다. 제출 폼에 요구된 형식과 실행 방법을 맞춘다.
5. 다음 시연을 한 흐름으로 구성한다: 거친/사진 제보→보고 상태와 실제 실패 대조→조회 변경→허용된 수정안→같은 검사·회귀→검토 카드→반복 재검증. 별도 짧은 사례로 다른 원인과 자료 충돌의 보류를 보여준다.
6. 대회 증빙은 트랙의 NeMo 요건과 예선의 별도 미션을 나눠 확인한다. 실제 모델·OCR·도구·작업 실행 기록을 시연 사건에 연결한다.

**완료 기준**

- 깨끗한 환경에서 문서의 명령으로 설치·서비스 접수·조사·후보 검사·기억 재조회가 재현된다.
- 최신 제출 폼의 필수 항목·기한·미션 완료 조건과 증빙이 확인된다.
- 화면·신청서·README·발표의 완료 범위가 실행 기록과 일치한다.
- 원인 확인, 후보 검증, 원본 적용, 서비스 회복을 혼동하지 않는다. NAT·OpenShell·Skills는 실제 연결/검증한 범위만 사용 기술로 보고한다.

## 6. 진행 순서와 세션 인계

- **시간 제약에 따라 [병렬 실행 프롬프트](parallel-work-prompts.md)의 A~D를 동시에 시작한다.** R1의 신뢰성 게이트를 우선 복구하면서 R2/R4의 독립 모듈과 R5/R6 준비를 병렬로 구현한다. 파일 소유권을 나누고 공용 경로의 최종 연결·전체 회귀는 편집이 끝난 뒤 수행한다.
- 구현은 로컬 자료와 doubles로 진행할 수 있다. 외부 모델의 종단 검증과 실제 프로젝트 실행은 실검증 가능 시점까지 미완료로 남긴다. R1의 완전성 게이트가 통과하기 전에 수정 실행·최종 성능을 확정하지 않는다.
- 실제 자료가 준비되면 R3의 실제 모델/작업 게이트와 R5를 수행한다. 자료 부재를 해결 성공으로 대체하지 않는다.
- R6의 제출 요건 확인·문안 초안은 먼저 진행할 수 있지만 최종 주장·수치·실행 묶음은 앞 단계의 실제 결과로 확정한다. 제출 기한이 임박했다면 검증된 제한 범위를 명시한 데모만 제출할 수 있고, 전체 계획 완료로 기록하지 않는다.
- 다른 세션에는 병렬 계획의 소유 범위와 해당 완료 기준을 전달한다. 메인 세션은 코드·재현·저장·화면·문서의 일치 여부를 검수한다. 같은 파일의 동시 편집과 다른 세션의 통과 결과 재사용을 피한다.
- 각 단계는 변경 파일, 기준 스냅샷, 실행 명령, 실제 결과, 외부 호출량, 미완료 게이트를 보고한다. 추가 범용 기능은 다음 단계의 조건을 만족하는 데 필요한 경우에만 도입한다.

기존 [대회용 1~5단계](competition-mvp.md)는 과거 구현의 이력이다. **남은 작업의 순서와 완료 기준은 이 R1~R6 계획을 따른다.** 제품 목표·권한의 기준은 기존 [제품 계약](../../design/product.md)과 [권한 정책](../../design/policy-security.md)을 유지한다.

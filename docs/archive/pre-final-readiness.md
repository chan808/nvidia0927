## 대회 요건

| 제공 이미지의 조건 | 판단 | 근거와 범위 |

[공식 Retriever 문서](https://docs.nvidia.com/nemo/retriever/)는 Retriever를 microservices 묶음으로 설명하고 Image OCR를 포함한다. [OCR 설명](https://docs.nvidia.com/nim/ingestion/image-ocr/latest/overview.html)도 NeMo Retriever OCR microservice로 분류한다. 제공 이미지의 활용 도구 목록 전체가 필수라고 단정하지 않는다. OpenShell/OS 격리 검증은 없다.

## 이번 개선

- 첫 화면을 제보·조사·수정안으로 연결하고 기존 합성 화면을 별도 페이지에 보존했다.
- 등록 씨드의 고정 가입 검사를 사본에서 실행해 현재 관측을 남긴다. TCP/Agolive API 호출이 아닌 신뢰 가능한 인프로세스 실행이며 최대 100건이다.
- “방금 가입이 안 돼요”로 후보를 찾고, 동작 기록을 명시적으로 확인한 뒤 현재 자료를 다시 읽는다. ID 없는 후보를 자동 확정하지 않는다.
- 가입/계정 만들기/방에 들어가기 표현, 소수점 ISO 시각, 새 사진의 시각 단서를 처리한다. 상대 날짜·명시 시각 우선순위를 유지한다.
- 접수와 작업을 같은 SQLite에 연결하고 중간 작업 실행 뒤 후속 답변 revision을 처리한다.
- 조사만/수정하지 마 요청을 구조화해 재시작 후 유지한다. 같은 사건의 후속 답변은 작업을 자동 반복하지 않는다.
- 프로젝트 변경 시 외부 분석·자동 준비를 해제하고 이전 결과를 비운다. KST 시각과 조사/수정 제안 호출량을 구분한다.
- 서버 사진 제한 8 MB, 패키지의 `.gitattributes`·Streamlit 설정 포함을 보완했다.
- 현재 규칙 관측 R 참조를 단서로 인정하면서 런타임 로그/확정 원인으로 승격하지 않는다.
- 이미 조회한 버전 도구의 모델 재노출을 줄이고 문자열 assistant 본문·tool 이름을 전달한다.
- 모델 5xx에는 확보한 자료로 최종 요약 1회만 요청하며 원래 실패를 보존한다. 시간 초과·권한 거절·요약 실패를 반복하지 않는다. 수정 작업자의 제안 1회 정책은 유지한다.
- 호스팅 최종 반환 스키마의 모든 평면 필드를 명시했다. 로컬 제한과 근거 검사는 유지한다.

## 단순 프롬프트와 비교

같은 Nemotron과 같은 코드·관측 접근권한으로 두 공개 합성 사례를 확인했다. 단일 프롬프트는 답변만 반환했고 코딩 에이전트 작업 성능 비교는 아니다.

| 사례 | 단일 프롬프트 | TraceBridge | 판단 |
| --- | --- | --- | --- |
| 가입 요청 키 오류 | 최초 서빙 실패 보존. 진단 1회에서 user_id→userId·WORK_CANDIDATE 제안 | 실제 diff·같은 검사·회귀·기록 연결 | 수정 방향 우위 미입증. 추가 가치는 실행·검증·기록 |
| 현재 500/TimeoutException | INVESTIGATE, 원인·수정 검증 미확정 | 같은 규칙 라우팅. 모델 조회 후 서빙 실패·관측 보존 | 분류 우위 미입증. 일반 조사 안정성 미완료 |

원인 찾기·시간·비용·기억 효과가 더 좋다는 주장은 하지 않는다. 규칙 파이프라인도 단순 사례의 라우팅을 처리할 수 있다.

## 실패와 검증 범위

일반 조사에서 HTTP 500이 반복됐고 첫 호출 실패도 있었다. 도구 응답 형식 하나가 유일한 원인이라고 결론내리지 않는다. 호환 전달 진단의 응답 2회는 성공했으나 상한 때문에 중간 종료했고, 이후 기본 클라이언트의 전체 실행은 다시 실패했다.

마지막 명시적인 최종 스키마 검사는 `chatcmpl-c01ad040-402f-4429-9a1a-5da9ec507600`으로 정상 반환했다. 500/TimeoutException을 원인 미확정으로 요약했다. 이는 **최종 반환 도구의 개별 실호출 성공**이며 새 스키마의 전체 일반 조사 성공으로 확대하지 않는다.

이번 추가 외부 호출은 실패를 포함해 **16회**다. 기존 4단계 2회와 구분한다. 실제 Agolive 자료는 전송하지 않았다. doubles와 GUI 검사는 실제 호출에 포함하지 않는다. 실패의 토큰 사용량 미반환은 미관측이다.

원자료: `output/pre-final-audit/pilot.json`, `tool_exchange.json`, `fixed_tool_exchange.json`, `final_schema_check.json`, SQLite `tracebridge-audit` 사건. 실패/진단을 보존하며 원자료·DB·임시 파일은 자동 제출하지 않는다.

## 최종 로컬 검사

기존 227개와 신규 22개를 합친 **249개가 통과**했다(51.14초). 과거 카드의 권한 확대 차단 검사는 이미 조회한 버전 도구가 재노출되지 않는 새 도구 목록에 맞췄고, 악성 도구 거절·과거 근거 배제의 기대값은 유지했다. `git diff --check` 통과, 등록 정책·6개 기준 파일 해시를 보존했다.

실제 서버를 재시작한 뒤 SQLite에서 위 사건과 후보 diff를 복원하고 같은 사건에 “원본을 수정하지 말고 조사만” 답변을 반영했다. 새 실행은 저장됐고 추가 모델·수정 호출은 없었다. 화면 증거는 `output/pre-final-audit/working-service.png`다. Windows 샌드박스의 임시 폴더 접근 실패와 정상 권한에서의 기능 검사 결과를 구분한다.

1. 현재 최종 스키마로 일반 조회→최종 반환을 종단 재검증한다. 서빙 오류와 자료 부족을 구분한다.
2. 허가된 프로젝트·접속 주소·로그·발생 시각·실행 버전으로 실제 사건을 검증한다. 이번 Agolive 확인도 HEAD `a25116f57c876d74c072b1151ee5a87494e2b11a`, 로그 파일 0개, Docker daemon 연결 실패였다.
3. 게이트 통과 후 최종 동일 조건 비교·묶음 재현·제출 준비를 진행한다. 범용 수정·자동 배포·다중 조직까지 확장하지 않는다.

# 제품 구축 단계와 완료 게이트

> 목표 설계와 계약입니다. 현재 구현 완료 여부는 [구현 상태](../current-state.md)에서 확인하세요.

이 문서는 한 번의 대회 제출 작업 목록이 아니라 TraceBridge 서비스 전체의 기능 의존성이다. 단계는 달력 일정이나 팀 인력 추정이 아니다. 다음 단계의 범위를 선택할 때 이전 단계의 근거가 실제로 작동하는지 확인한다. 각 단계의 상태는 [현재 구현과 간격](../current-state.md)에서 갱신한다.

| 단계 | 사용자에게 추가되는 능력 | 필수 의존성·완료 게이트 |
| --- | --- | --- |
| 0. 연구·데모 | 제보와 합성 관측의 항목별 대조, 두 샘플 재현, 읽기 전용 Agolive 코드 검색 | **현재 기반.** 합성/실서비스 경계를 UI와 문서가 정확히 설명 |
| 1. 실제 사건 상관 | 한 프로젝트의 제보·프론트 실패 캡처·로그/trace·배포 버전 연결 | 허가된 개발/스테이징 사건에서 사용자 로그 복붙 없이 한 요청을 식별. 0/복수 후보는 보류·질문 |
| 2. 적응형 조사 | 규칙 빠른 경로와 Nemotron의 가설·반증 조회, 원인/사용법 구분 | 증거 변경에 따라 다른 도구·결론을 택하고 근거 ID를 검증. 잘못된 확정률 평가 |
| 3. 협업과 라우팅 | 여러 제보의 사건 묶음, 중요도, 소유자·온콜·역할별 보고, 사건 기억 | 인증·인가, 프로젝트 정책, 감사 기록. 제보자와 내부 담당자에게 다른 정보가 보임 |
| 4. 검토 가능한 수정 | 프론트/백엔드 담당 영역별 격리 패치, 수정 전후·회귀 검사, diff/PR | 대상 커밋·실행 격리·허용 명령. 검사 실패를 성공으로 표시하지 않음 |
| 5. 정책 기반 자동 해결 | 선택된 비운영 적용과 낮은 위험 변경의 자동 릴리스·사후 검증 | 프로젝트별 명시 정책, CI/배포 연결, 점진 적용·모니터·중단·롤백·감사. 보안/스키마 등 고위험 변경은 기본 제외 |
| 6. 여러 조직·확장 | 프로젝트별 연결기·비용·보관·권한 격리, 주기 검사와 반복 장애 분석 | 테넌트 격리·장애 복구·부하 평가·운영 지원 체계 |
| 7. 능동 품질·보안 | 승인된 API/브라우저 회귀 검사와 별도 보안 결과 수용·개선 권고 | 환경·계정·요청률·대상 범위, 오탐 검토. 운영 능동 스캔은 독립 정책 |

각 단계는 사용자 가치가 독립적으로 있어야 한다. 1·2단계가 해결하는 **사건 자동 식별과 신뢰 가능한 분류**가 없는 상태에서 기억 검색·자동 수정·보안 스캔을 추가해도 프롬프트+MD 대비 장점을 입증하지 못한다. 4·5단계가 없으면 제품은 자동 코드 수정 서비스라고 설명하지 않는다. 5단계까지 작동해도 모든 오류의 자동 해결을 약속하지 않는다.

## 구성 요소별 확장 방향

- **입력:** 단일 텍스트 폼 → 프론트 실패 캡처/알림/CI 입력 → 인증된 외부 통합. 공개 접수에는 남용 방어와 내부 정보 비공개가 선행된다.
- **연결기:** 로컬 JSON·코드 검색 → 로그/APM/배포 SHA·SCM → 읽기 전용 DB 진단 → 다중 공급자. 프로젝트별 데이터 범위가 정책으로 정해진다.
- **조사:** 현재 두 전용 규칙 → 사건 후보·반증 루프 → 스택별 검사기. 모델은 선택·가설에 집중하고 최종 확정은 검증된 근거에 묶는다.
- **실행:** 샘플 앱 테스트 → 허가된 프로젝트의 격리 재현 → PR/CI → 선택적 비운영·운영 자동화. 각 단계마다 권한과 검증 게이트가 커진다.
- **기억:** 사람이 검토한 사건 카드와 정확/전문 검색 → 검색 누락이 측정될 경우 임베딩/재순위화. 과거 사건의 결론은 언제나 현재 증거로 재확인한다.

## 제품 출시 판단

내부 시범 운영은 단일 허가된 프로젝트에서 실제 자료로 사건 상관·분류가 반복 검증된 뒤 시작한다. 여러 팀으로 확장하기 전에는 소유자 라우팅, 알림 공개 범위, 모델 전송 범위, 원본 로그 보관, 비용 상한을 검증한다. 자동 수정은 재현/회귀 검사와 격리 실행이 안정된 후 활성화한다. 자동 릴리스는 복구·사후 관측의 실패 사례까지 재생 시험한 뒤 프로젝트별로 켠다. 제품을 계속 만들지의 기준은 [평가와 운영](evaluation-operations.md)의 동일 자료 접근권한 비교 결과다.

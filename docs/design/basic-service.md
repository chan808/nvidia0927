# 기본 서비스 구현 계획

2026-09-29. 공개 제보를 현재 관측과 대조하고, 허용된 수정 작업과 검증된 사건 지식으로 연결한다.

## 계약

1. 소유자가 프로젝트·서비스별 공개 접수를 켠다. 외부 제보자는 운영자 자격 증명 없이 접수하고 만료형 접수 토큰으로 본인의 상태·후속 답변만 다룬다. 내부 코드·로그·모델 출력·다른 제보는 공개하지 않는다.
2. 제보 내용과 첨부 메타데이터는 주장이다. 현재 요청 연결·자료 완전성·계약 대조로 안내, 질문, 수정 후보, 담당자 검토, 미해결을 구분한다. 난이도·위험·중요도는 각각 기록하고 소유자의 수정 정책을 대신하지 않는다.
3. 기본 자동화는 조사다. 소유자가 선택한 정책에 한해 수정 후보를 자동 준비한다. 비운영 원본 자동 적용은 서버 설정과 PC의 별도 정책이 모두 허용하고, 작은 후보의 전후·회귀 검증과 회복 검사 등록을 만족해야 한다. 배포·서비스 재시작은 이 권한에 포함하지 않는다.
4. 실패·보류·검증된 후보·원본 적용·서비스 회복을 다른 상태로 기록한다. 재전송과 중복 접수는 기존 작업을 재사용하며 외부 호출·적용을 무조건 반복하지 않는다.
5. 사건은 모두 저장한다. 검색 가능한 매뉴얼은 기존 검토 계약을 유지하고, 명시적으로 선택한 경우 등록한 회복 검사의 성공 카드만 자동 승인한다. 미확인 가설과 실패 기록은 해결 매뉴얼로 자동 승격하지 않는다.

## 구현 순서와 검사

- SQLite/PostgreSQL 공통 공개 정책·접수·속도 제한 저장, 이전/내보내기 호환.
- 공개 접수·조회·후속 답변 API와 운영자 설정, 제보 화면, 프록시 공개 경로.
- 현재 관측 기반 자동 평가, 멱등 수정 작업 연결, 비운영 적용과 회복 작업 연결.
- 지식의 검증 수준 표시와 회복 성공 카드의 선택적 승인.
- 공개 정보 경계, 다른 토큰·프로젝트·변경된 정책, 중복·중단·취소·실패·후속 답변, 실제 파일 수정/HTTP 회복을 검사. 기존 회귀를 실행한다.

## 후속 확장

아래는 후속 설계이며 현재 기본 서비스의 구현 기능에 포함하지 않는다. 공개 전 운영 조건은 [점검표](../guides/basic-service-rollout.md)에 있다.

### 매뉴얼과 챗봇

- 내부 검색 재사용 승인과 외부 공개 승인을 별도 상태로 둔다. 공개 승인은 운영자가 검토하며 자동 회복 성공만으로 공개하지 않는다.
- 공개 문서는 증상·적용 가능한 서비스/버전·사용자 수행 단계·주의 조건·확인 시각·근거 문서 ID만 포함한다. 내부 경로·로그·원문 제보·사용자 식별 자료는 제외한다.
- 챗봇은 공개 승인 문서에서만 답하고 출처와 적용 조건을 표시한다. 근거가 없거나 현재 버전에 맞지 않으면 추가 질문 또는 새 제보로 연결한다.
- 문서 정정·반려·버전 만료 시 검색과 캐시에서 즉시 제외한다. 정확 검색/키워드 기준선과 벡터 검색을 같은 질문·예산으로 비교한다.
- 완료 기준: 내부 카드가 답변에 노출되지 않음, 출처 없는 해결 확정 없음, 반려·정정의 검색 반영, 실제 질문 집합에서 답변·보류 품질 기록.

### 능동 점검

- 소유자가 대상 서비스·환경·endpoint/사용자 여정·코드 경로·허용 메서드·호출 예산·실행 시간·제외 경로를 등록한다. 읽기 전용 점검으로 시작한다.
- 점검 결과는 발생 시각·요청 ID·응답/기대 결과·실행 snapshot·재현 절차·출처를 가진 새 사건으로 접수한다. 점검 에이전트의 설명을 검증된 버그나 취약점으로 바로 승격하지 않는다.
- 동일 증상/버전의 반복 발견은 기존 사건에 관측을 추가하고 회복 뒤 재발은 다시 연다. 제보와 점검에서 온 자료의 출처는 유지한다.
- 상태 변경 API, 성능 부하, 인증 경계/취약점 검사에는 별도 정책과 격리된 대상이 필요하다. 점검 권한은 원본 수정·배포 권한을 부여하지 않는다.
- 완료 기준: 허용 범위 밖 호출 없음, 예산/취소 준수, 현재 버전에서 재현한 증상·반증 기록, 중복 억제와 재발 기록, 담당자가 검토 가능한 근거.
